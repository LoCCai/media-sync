# Unified project status (single source of truth)

The pushed execution 0055 backend-authentication implementation is commit `f19bfaa` (the frozen planning baseline is `4564b2a`). It resolves a required typed operator credential before bind, supports an optional distinct Bearer credential, enforces exact Host/Origin policy, rotates a process-local HttpOnly `SameSite=Strict` session cookie, requires CSRF on unsafe cookie-authenticated methods, applies deny-by-default ASGI protection with an exact anonymous allowlist, accepts only strict bounded login JSON, and wires the credential/origin contract into Docker Compose. Its 190-test auth/API focus and complete offline regression (`2811 passed, 14 skipped, 1 warning in 561.43s`) pass, as do 69 Web tests and all locally available static/build/docs/package gates. Three skips are Windows/POSIX differences; 11 real-PostgreSQL races and Docker validation were unavailable on this workstation and are not claimed.

The current working change advances only the playback-evidence foundation. A complete unique `matched` media-server lookup now derives a context-bound `observation_fingerprint`; `not_found` derives and exposes none, and the Web lookup response type mirrors that read contract. Revision `0008_playback_evidence` adds an append-only ledger with constrained canonical identities, safe digests, timestamps, `RESTRICT` author/publication-Job parents and a unique observation identity. Its repository provides first-writer create-or-exact-replay semantics, explicit identity conflict, SQLite writer reservation and a PostgreSQL unique-conflict path. The current complete suite passes `2868 passed, 22 skipped, 1 warning in 558.19s`; the skips are 3 Windows/POSIX cases, 11 existing Operation PostgreSQL cases and 8 new PlaybackEvidence PostgreSQL cases without a configured test URL. Web 69 plus format/check/build, Ruff/format across 727 files, strict mypy across 105 source files and compileall pass. Real PostgreSQL and Docker were not run. This is not authenticated playback confirmation: the confirmation service/API/UI and qualification schema v3 do not exist. The isolated Author/Job/PlaybackEvidence PostgreSQL harness does not establish complete-schema or production PostgreSQL support. Console v2 and `/legacy` also still lack login/session/CSRF integration, so the Web console is not currently an operable administration surface. Consequently `playback_evidence` remains `NOT_IMPLEMENTED`, live playback remains `NOT_RUN`, and every execution 0047 live qualification row remains `NOT_RUN`. Provider task completion remains unsupported by the common APIs and is not a 0054-B or 0055-A claim. Execution 0047 remains the open P0 operator gate; absent capabilities are `NOT_IMPLEMENTED`, not unexecuted live rows. This table is the canonical status view; per-execution detail lives in [`executions/`](README.md) and evidence in each verification record. Update this page at every closeout.
