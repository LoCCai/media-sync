# Frozen implementation plan

1. Preserve existing policy v1 and `bili-scan-v1` upload-only behavior. Add explicit Bili policy v2 scope `uploads`, `dynamics`, `both`; never silently broaden old subscriptions or create competing Account/Author subscriptions. A composite cursor binds account/author/upstream SHA and retains the original upload cursor and independent dynamic head/history progress. Scope changes retain inactive feed state, use current schedule/Run fences and do not reinterpret the old watermark as coverage.
2. One bounded feed unit per Job, fair upload/dynamic and head/history selection. Dynamic discovery persists a bounded private immutable page snapshot before its checkpoint can reference it; cursor/report contains only scope, digest and bounded progress, never body/media URLs. A discovery-only unit can publish zero content and retained pending work. Consume pending identities only after exact DID/type/normal-author/pub_ts detail confirmation; retain next offset until page entries are consumed, do not discard remaining items at the limit, do not interpret missing/changed detail as successful consumption. Detect repeated offsets and report conservative restart/partial/source-end truth. Snapshot files are account/author/SHA-bound, private, digest-verified and confined; no implicit garbage collection or reuse across accounts.
3. Implement original protocol facts from fixed sources, without copying GPL implementation or third-party response fixtures. Use the locked Bili client/signing/browser account path: feed/space; dynamic detail `id=DID`; exact same-DID OPUS detail when a summary cannot prove full text. WORD/DRAW support old desc/draw and OPUS text/static pictures. Normal-author MID must match subscription; never descend into a forwarded `orig`, a season, article, paid or unknown subtype as if it were an owned original. Retain truthful unsupported-component diagnostics rather than claim full media support. OPUS parsing must not silently omit unsupported content paragraphs while claiming complete text.
4. AV dynamic and video are distinct identities. Revalidate ordinary View aid/bvid/owner/pages/CID using the existing media contract; dynamic pub_ts is not video pubdate. Keep the dynamic text/own DID plus an explicit ordinary-video reference, deduplicate the ordinary AID, and do not adopt a collaborator's or forwarded video's ownership. Preserve the existing maximum normalized-record budget; reserve two records for an AV reference. New dynamics/both subscriptions require max_items at least2 (default30); explain this constraint in UI/docs, retain upload-only max_items1, and leave a tail AV pending rather than exceed the budget.
5. Add sealed versioned coverage and exact identity cross-checks through bridge, real shim, normalizer, CLI, scheduler and atomic bounded ingestion. Cursor, content/assets, refresh observations and successful Run publish together. Keep cancellation, lease, schedule, expected checkpoint, source digest and durable-success recovery behavior. New dynamic image slots require exact dynamic/OPUS refresh with current author/DID proof and complete ordered image identity; never treat a numeric DID as an AID or allow a changed attachment to resolve an old asset. Existing ordinary-video refresh remains responsible for referenced AIDs.
6. Expose scope and honest per-feed progress in subscription UI/API/CLI, keeping raw state and credentials private. Verify synthetic locked-client request/signing budgets and response shapes, more-than-one-page restart/resumption, pending retention/deletion/drift, snapshot tamper and wrong binding, WORD/DRAW/OPUS/owned/foreign AV, namespace/dedup, cancellation/CAS/recovery and offline real download/archive/local export idempotence. No media-server connection is required for local output; arbitrary text/gallery files are not claimed playable in Emby/Jellyfin.
7. Use incremental tests and independent review while implementing, then freeze source before final affected regression. Complete-directory snapshots, final-source affected checks, environment skips and any failures are distinct evidence, not summed or mislabeled. Save bilingual goal/plan/progress/verification plus source evidence, update project status/deployment guidance, make bilingual local commits, non-force push GitHub and fresh-fetch equality. Do not claim completion while the production entry points or required output paths remain unwired.

No production login, Cookie entry, subscription mutation, live lookup/retry/capture, download/export, deployment, media-server action or supervisor restart. The other five creator profiles and remaining three Cookie validators stay required; this execution does not replace the original goal with Bili-only support.
