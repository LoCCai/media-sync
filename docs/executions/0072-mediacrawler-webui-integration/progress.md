# Progress

Status: the first thin integration slice is implemented in commit `ea64938`. Its focused checks, complete Python unit suite, complete 782-test media-sync Web suite, staged build of the real pinned upstream React source, and production-dependency audit pass. It is not deployment-qualified: the current Docker image and online deployment have not been validated, and the build-only development graph retains eight audit findings.

## Implemented first slice

- Added a separate deployment-level MediaCrawler license acknowledgement. It defaults to false and accepts only exact `true`/`false` values. Until the operator reviews the pinned non-commercial learning license and explicitly opts in, the upstream application is not imported or constructed and every authenticated `/crawler` HTTP path, including start, returns the same no-store `503 license_acknowledgement_required`; the existing supervisor CLI gate remains independent.
- Mounted the pinned MediaCrawler FastAPI application at `/crawler` before the media-sync SPA fallback when that gate is enabled. Existing operator-session authentication protects the page and HTTP API; unsafe Cookie-authenticated requests retain media-sync's CSRF requirement. The upstream development CORS grant is removed. Only the exact upstream log and status WebSockets are admitted, and only for a valid browser session with the configured exact Host and Origin.
- Added an isolated Docker build stage for the pinned upstream React WebUI. In its temporary copy, an exact security patch selects Axios 1.18.0, follow-redirects 1.16.0, and form-data 4.0.6, regenerates the copied lock, performs a clean install, and requires the production audit to pass before applying deterministic `/crawler/` base/API/download/WebSocket/CSRF, favicon, and QR-panel adaptations. A fresh local run passed every step, built 1,836 TypeScript/Vite modules, and verified the expected prefixed assets and bundle seams. Only generated browser assets are copied to the final image stage; the locked checkout and its lockfile remain unchanged, and the complete Docker stage itself remains unexecuted.
- Replaced the upstream manager's ambient `uv run` assumption with a media-sync adapter that verifies the locked checkout and configured dedicated Python first, then launches the child with that exact interpreter and checkout. The upstream `/api/env/check` probe is replaced with a deterministic report for that already-qualified commit/interpreter; missing or mismatched runtime material returns the fixed `mediacrawler_webui_unavailable` response with `Cache-Control: no-store` and no fallback installation.
- Replaced the upstream launch/read/stop seam with one no-shell managed process per run generation. POSIX children start in a new session; Windows children use a new process group plus a Job object. Operator stop, normal exit, failed start, and root-application shutdown close the exact process tree before private resources are released. The root lifespan explicitly awaits this callback because Starlette does not propagate a mounted application's lifespan.
- Bounded and sanitized the retained upstream console stream: each displayed message is capped at 8 KiB, an overlong physical line is discarded across read chunks, history retains at most 500 entries, the live queue at most 512, and both known Cookie values and generic credential shapes are redacted. The public `current_config` has its Cookie cleared. High-frequency QR/status/log polls remain authenticated and no-store but are excluded from request-finished logging; start remains logged once.
- Confined upstream data to separate managed roots: `webui-output` for crawl data/media, `webui-profiles` for persistent browser login state, and `webui-private` for Cookie handoff. A Cookie is capped at 64 KiB, absent from the operating-system parent launch arguments and public configuration, and passed through an exclusive `0600` one-shot file. The exact file is removed on argument/start failure, after the child reads it, on normal completion or stop/shutdown, and by a narrowly scoped startup sweep for abandoned handoffs.
- The child fixes the checkout working directory, persists login state, disables CDP mode, limits upstream concurrency to one, and sets both the pinned spelling `ENABLE_GET_MEIDAS=True` and the forward-compatible `ENABLE_GET_MEDIAS=True`. It passes `SAVE_DATA_PATH` and the persistent profile pattern from media-sync-owned paths rather than browser-selected arbitrary roots. Its environment is rebuilt from a browser-only allowlist that excludes operator/API secrets, and it installs the existing media-sync policy that selects the image's bundled Playwright Chromium rather than an ambient browser channel.
- Added the minimal browser QR relay for the current singleton crawler attempt. The existing upstream `show_qrcode` hook accepts only bounded raster input, strips metadata by re-encoding to PNG, writes atomically outside the checkout, and cleans up when the child exits. The authenticated endpoint serves only a regular current file of at most 2 MiB and at most 180 seconds old with `no-store`, `nosniff`, and a SHA-256 digest; the patched upstream panel polls it only while a QR login is running and revokes replaced browser object URLs.
- Added the console sidebar/login return path and bilingual deployment guidance. The supported operator entry is `/crawler/`; no alternate unauthenticated upstream listener is introduced.

## Deliberately not connected

- This slice does not connect console output to durable Subscription dispatch, history/backfill state, scheduled incremental runs, task reconciliation, completed-output ingestion, or deterministic folder/NFO publication. Console artifacts remain upstream interactive output until a later bounded ingestion slice is implemented and verified.
- media-sync does not ingest arbitrary upstream logs, browser profiles, command text, or every file visible in the upstream data browser as durable authority.
- MediaCrawler continues to own interactive login, crawl control, platform requests, and upstream media download. media-sync continues to own authentication and, in later slices, scheduling, monitoring, defensive ingestion, and Emby/Jellyfin-compatible folders/NFO.
- Execution [0071](../0071-remaining-runner-output-diagnostics/progress.md) is paused in delivery order, not completed. Its missing runner diagnostic coverage and previously discarded output are not repaired or reclassified by this integration.
- An Emby/Jellyfin server connection remains optional. This slice neither requires one nor proves a real server scan or playback result.
