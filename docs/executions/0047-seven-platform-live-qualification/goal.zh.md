## 目标结果（由操作者逐平台记录）

1. **阶段 B 基线先行**：干净 clone → 完整套件 → Docker 构建 → health/ready → 重启持久性 → 备份恢复演练（见 [`docs/operations.zh.md`](../../operations.zh.md)）。只有阶段 B 全绿，执行 0041 才从“打包交付”升级为“部署通过”。
2. **阶段 C 金丝雀**：Bilibili（最复杂媒体链：progressive/DASH/合并/多分 P/FLV/备用 CDN/ffmpeg/Emby 播放）与小红书（最复杂权限链：QR/saved-session、创作者权限、签名 URL、混合媒体）先跑完整矩阵；两者均至少达到 Experimental 后才推进其余平台。
3. **逐平台样例矩阵**（不是“每平台一个创作者”）：主路径创作者；覆盖本仓库所声明形状的创作者（如 B 站多分 P + DASH + FLV；小红书视频/多视频/实况）；无媒体或部分媒体创作者；一次过期登录重认证；一次内容删除或 URL 失效场景。每格记录实际发生的情况。
4. **增量性拆成两行**：(a) 无变化重跑——新 Content = 0、新 Asset = 0、下载字节 = 0；(b) 真实增量——通过操作者可控测试账号在两次运行间发布一条新内容，或以两个捕获的真实响应放宽水位/分页边界。立即重跑永远不能充当增量行。
5. **Emby/Jellyfin 对 Supported 等级是强制项**：真实只读挂载媒体库、触发重扫、验证剧集/季/集身份、NFO 解析、海报/背景图，且每平台至少抽样播放一个可播视频（图片/文章平台验证 NFO/图集/正文渲染）。记录媒体服务器版本。只有目录列表仅证明导出器，不证明产品。
6. **支持等级与最低发布条件**：Supported / Experimental / Metadata-only / Blocked External / Unsupported。v0.1.0-rc1 要求两个金丝雀达到 Supported、其余平台如实分级；此后项目自我表述为“七平台适配框架；资格状态见矩阵”，绝不表述为“支持七个平台”。
7. **允许缺陷循环**：真人运行必然暴露真实缺陷（字段漂移、挑战变化、会话过期、CDN 头、容器怪癖、NFO 兼容）。每个缺陷建立编号修复子执行（改代码 → 自动回归 → 重跑受影响平台 → 重跑受影响同类平台）后父记录才可关闭。禁止的仍然是在验收记录里偷偷改代码。
