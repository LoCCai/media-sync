# Frozen staged plan

1. Stage A — immutable observed content ownership. Content identity remains (platform, remote_type, remote_id). Inserting a new identity binds it to its creator; later same-author metadata refresh remains allowed, while a different author gets a fixed secret-safe ContentOwnershipConflictError. Native SQLite/PostgreSQL upsert must condition the actual conflict update on the existing author_id, never check then overwrite; no metadata/tombstone/path/provenance mutation on rejection. Keep savepoint rollback and caller transaction usability. PostgreSQL Author creation must use its native conflict handling so a concurrent first discovery can reach the same ownership guard. Other dialect fallback locks a found row and never reassigns its author. Do not rewrite existing historical ownership or provide implicit takeover/recovery.
2. Stage A — propagate a fixed content_ownership_conflict code through ingestion/scheduler/CLI and operator-friendly Web diagnostics. It must not retry automatically or trigger an account-wide circuit breaker; tell operators the original content remains with its prior author and to inspect the subscription/source, not erase data or re-login blindly. Keep exact Run/Job truth and failure cleanup, no secrets or raw remote/account/content identities in error text. Old committed batches retain their existing semantics; the conflicting batch or bounded unit cannot advance its checkpoint or create refresh observations/assets. Do not roll back unrelated earlier committed work by claiming all legacy multi-batch runs are one transaction.
3. Stage A acceptance — demonstrate the original overwrite with a regression, then verify same-author refresh, cross-author metadata immutability and author/savepoint rollback, separate dynamic/upload namespaces, races and winners, stale ORM identity-map handling, and actual normalized ingestion/scheduler error/Run/Job/provenance/pipeline behavior. Test SQLite and available PostgreSQL; unconfigured PostgreSQL is NOT_RUN. Include strict fixed-code/UI rendering, original media/archive/export and platform regressions. Save bilingual actual failures/checks, commit bilingual changes, non-force push and fresh-fetch equality.
4. Stage B (not yet implemented) — explicit versioned subscription capture scope (uploads, dynamics, both). Preserve old v1 upload-only semantics and existing upload cursor exactly; one Account/Author subscription cannot be replaced by two competing subscriptions. A composite cursor must bind account/author/SHA and retain independent feed progress; no copied watermark or silent scope expansion. One bounded feed unit per Job, fair selection, shared max_items budget and accurate partial/source-end reporting.
5. Stage C (not yet implemented) — establish source-backed raw dynamic author/WORD/DRAW-or-OPUS/AV identity and attachment shapes, plus an exact bounded media refresh authority. Current locked MediaCrawler only has feed/space offset pagination, no dynamic detail method, and discards attachments; current Bili refresh only supports ordinary VIDEO/COVER. A feed body can disappear between retries: either establish an exact detail contract or persist a bounded private immutable page snapshot before consuming entries. Never drop remaining page items by moving offset after max_items truncation, put media URLs in public checkpoints, or invent remote endpoints/fields from synthetic fixtures.
6. Stage D (not yet implemented) — wire original text, static galleries and owned ordinary-video references end to end through explicit scope/UI/CLI, real locked client/shim, receipt sealing and source author proof, atomic cursor ingestion, exact-source refresh, safe media download, archive and local Emby/Jellyfin structure. Keep dynamic IDs separate from AIDs; repeated AV references deduplicate without reattributing somebody else's video. Unknown/repost/article/live/paid shapes need truthful unsupported/retained diagnostics, not recursive capture of unrelated creators. Test same-second/pinned/reordered/looping offsets, pending retention, snapshot/detail tamper, cancellation/lease/CAS/recovery, image order/replacement and video owner/AID/BVID/CID, and offline real-pipeline export idempotence. A phase is not complete until the production path is reachable and verified; live qualification remains separate.

No production login, Cookie entry, subscription mutation, capture retry, download/export, deployment, media-server action or supervisor restart. Stage A may be published independently only as a documented prerequisite; Stages B–D and the seven-platform objective remain open.
