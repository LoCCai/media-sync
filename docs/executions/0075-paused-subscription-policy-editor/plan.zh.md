# 计划

状态：**已在 `aec3eac` 完成本地实施**。

## 1. 冻结修改契约

- 增加包含五项可编辑控制和 `expected_schedule_revision` 的类型化策略更新命令。
- 修改前解析并校验当前封闭 MediaCrawler 策略；精确保留全历史确认及不透明作者引用。
- 对不存在、已删除、已启用、忙碌、修订过期、不支持的适配器及无效策略/选项返回固定公开错误码。

## 2. 用一个短数据库事务取得所有权

- SQLite 预占 writer；PostgreSQL 锁定精确订阅行。
- 在同一事务内复核活动 Job、非终态 Run 及活动 operation 所有权。
- 比较修订、原子更新全部字段，并且只有真实变化才增加 `schedule_revision`。
- 用测试确认检查点、水位、扫描/交付行、时间证据、失败计数、历史及文件均未被修改。

## 3. 控制面共用服务

- 增加严格拒绝额外字段的 `PUT /api/v1/subscriptions/{id}/policy`，只返回白名单结果。
- 增加 `media-sync subscription policy` CLI 命令。保留既有 B 站范围兼容命令，但新 UI 统一走通用服务。
- 所有客户端可见信息保持固定且不含引用值。

## 4. 替换狭窄的详情编辑器

- 把订阅详情中仅 B 站范围的编辑器扩展为完整封闭策略集合。
- 只从验证过的新鲜详情响应填充控件；说明启用态为何不能编辑；输入损坏或没有变化时禁用保存。
- 请求同时绑定订阅身份、调度修订、操作者会话 epoch、弹窗生命周期及单个在途 generation。成功保存后更新详情和列表，但订阅继续暂停。

1. 增加应用/集成测试，覆盖原子性、并发、空闲栅栏、精确保留、B 站交付重新资格及 no-op。
2. 增加 API/CLI 契约与 Web utility/source 测试，覆盖严格校验、脱敏和过期响应处理。
