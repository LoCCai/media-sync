# 粘贴 Cookie 登录计划草案

- 日期：2026-09-05
- 状态：DRAFT — 安全及生命周期决策待定；不是实现契约
- 前提：紧急登录运行时/诊断发布保持独立增量。

## 顺序交付

1. 审阅只读发现并明确下述决策。在实现 Cookie 功能前，冻结并提交准确的中英双语目标/计划。保留七平台目标与既有凭据/生命周期保护。
2. 建立独立的应用自管私密凭据存储。部署中的 `/run/secrets` 是操作者管理、可能只读的输入来源，不是上传目的地。现有 `SecretResolver` provider 只负责读取，并不意味着已经存在安全写入流程。编码前明确引用接入、权限检查、原子发布、回滚和恢复。
3. 首先只为 B 站打通完整流程：已认证控制台输入、有界私密候选处理、全新环境远程自身会话验证、成功结果持久化、如实状态展示，以及通过现有 Cookie 消费链复用。要求 `/x/web-interface/nav` 严格肯定已登录并返回经过校验的当前用户身份；具体响应契约和绑定策略必须先冻结。
4. 执行安全、生命周期、集成和 UI 测试，再请求操作者参与真实 B 站验证/保存/复用。模拟响应或另一个账户已有的有效 profile 不是真实证据。无效候选和网络不确定场景必须证明原有效凭据得到保留。
5. 逐个平台定义并实现其余契约。小红书和知乎已有值得核查的自身信息端点；微博已有远程登录标志，但需要身份契约。快手列表成功尚未证明具有认证权威性。抖音和贴吧需要超越现有本地标记检查的远程认证证明。界面必须明确保持未实现验证器不可用。
6. 每个实际增量后更新中英双语进展、验证及已实现/待实现状态。使用带清晰说明的双语本地提交，经对应审查和验证后发布。本草案任一步骤都不表示 Cookie 支持、七平台验收或播放已经完成。

## 必要安全边界

- 敏感输入仅通过现有操作者认证控制面，并继承准确 Host/Origin 与浏览器 CSRF 检查；非 loopback 访问继续要求 HTTPS。不增加匿名导入入口，不持久化到控制台 local/session storage。具体 API 与 bearer 策略仍待设计。
- 限制请求及私密子进程输入字节数。确定性校验 Cookie 语法和控制字符，包括明确重复名称策略。不得接受用户指定的验证 URL 或任意 Cookie 域名；目标由所选平台的允许列表派生。冻结重定向/代理行为与时限。
- 使用临时全新候选环境。不继承有效账户 profile，不根据公开端点推断成功，不将上游 `update_cookies` 当作证明，不允许交互式二维码回退。保留既有有界子进程及完整进程树清理保证。
- 原始 Cookie 不进入 SQLite/PostgreSQL、Operation 摘要、结构化诊断、日志、argv、URL、支持包、证据或 Git。不暴露完整上游自身信息响应，其中可能包含邮箱等个人字段。成功路径之外也审查 HTTP 校验/错误路径。
- 与登录/采集消费者共用既有账户锁；成功结果绑定准确账户及观察到的凭据/配置状态。用比较并交换阻止陈旧成功和失败覆盖。验证成功前，进行中的候选不得成为调度器或下载的凭据来源。
- 已验证候选安全提交前保留原有效材料。失败、取消、网络不确定及崩溃恢复不得静默替换、过期或认证原材料。本草案不授权无界重试或自动登录。

## 下次需冻结的决策

1. **账户生命周期：** v1 支持新建账户、替换已有 Cookie 账户、转换二维码/已保存会话账户，还是明确限定的子集；如何表示待验证候选及准确操作，又不破坏现有认证状态转换规则。
2. **身份绑定：** B 站规范化远程用户身份、首次绑定、后续不同用户替换，以及最少持久化/公开身份字段。本地显示名称不是远程身份依据；现有 Account 行没有此类绑定。
3. **私密存储：** 自管存储的归属/位置和 provider 接入、原子写入/提交顺序、孤立材料恢复、备份/还原及凭据替换。此处不选择最终 secret scheme。Linux 必须具有仅所有者可访问行为；Windows ACL 与 DPAPI 的选择，以及不支持平台的行为仍未解决。仅调用 POSIX 式 `chmod` 不是 Windows 安全方案。
4. **契约及结果：** 准确请求/协议形状、大小限制、已认证/无效/不确定/不支持的区分、敏感正文错误脱敏、取消与超时语义及兼容性。本草案不授权臆造端点或数据库迁移。
5. **发布证据：** 确定性离线测试、受支持操作系统验证门、真实 B 站响应验收和操作者交接；各后续平台的权威证明与独立开启条件。

## 计划验证

覆盖自身认证成功、过期/伪造 Cookie、伪造本地登录标记、仅公开数据访问成功、畸形/超大/含控制字符输入、重复名称、重定向/目标限制、响应歧义及上游失败。覆盖无旧 profile 污染、无二维码回退、账户/凭据漂移、重复提交、取消、进程树清理、私密存储/数据库提交失败及重启恢复。在错误、日志、数据库、Operation、导出和支持包中检查秘密哨兵值。验证 UI 可用状态，无效或未实现情形不能显示保存/认证成功。本草案阶段全部功能验证保持 `NOT_RUN`。
