# 粘贴 Cookie 登录目标

- 日期：2026-09-05
- 状态：用户目标已接受；设计草案，尚未冻结或实现
- 审计背景：登录诊断和紧急 Node.js/二维码转发修复是独立增量；记录本草案时 HEAD 为 `7268352`。

## 已接受目标

允许操作者在已认证的本地控制台粘贴抓取到的平台 Cookie，向平台验证其有效性，只有取得可信远程证明后才保存为已认证。不要让操作者把凭据发到聊天或 GitHub。新增需求保留原定七平台登录、订阅作者、抓取图文/视频和 Emby/Jellyfin 兼容归档目标，不替代二维码登录，也不缩减最终平台范围。

首个实现切片应以 `/x/web-interface/nav` 的已登录自身会话响应为依据，打通明确支持的 B 站完整流程。其他平台必须先建立各自权威远程认证契约，再依次接入。在实现与验证完成前，界面必须如实显示相应平台的粘贴 Cookie 流程不可用，不能据本次审计宣称七平台已经支持。

## 验收方向

1. 使用全新候选环境验证，不复用旧的有效 profile，不回退到二维码。Cookie 存在、导入浏览器成功、公开内容可访问和 `update_cookies` 完成都不构成认证证明。
2. 只有有界、平台专用的远程自身身份认证成功，才可授权持久化。凭据无效、网络失败、风控挑战、响应不明确或验证不受支持，都不得变成认证成功。
3. 替换候选失败或结果不确定时，保留原有效凭据和 profile。发布任何成功替换前，使用相同账户互斥边界和比较并交换机制阻止陈旧结果覆盖。
4. 原始 Cookie 不进入数据库行、Operation、日志、诊断、命令参数、URL、控制台 local/session storage、文档或 Git。持久化仅通过明确设计的私密凭据存储，现有消费链只获得不透明引用。
5. 实现测试与操作者参与的真实登录、复用、抓取及播放证据分开记录。执行相应验证前，功能验收保持 `NOT_RUN`。
