上一轮属于有效推进：已认证 UI 证据、独立环境过滤实验和源码/浏览器通道差异记录于 `db6c3c7`。恢复时工作树清洁。本轮修复这些共用链路，不推断部署平台登录成功。

## 已实现

1. 登录、作者和详情执行共用拒绝秘密变量的浏览器环境，保留已安装缓存路径；不透传任意代理/Python/debug/后台设置或父进程私有输入。
2. 内存中的 bundled Chromium 策略包装锁定工厂及常规启动，接入三条入口，包括数字 Bilibili aid 详情。移除冲突通道、显式选择已安装可执行文件，保留上游选项、profile 和生命周期所有权；上游 checkout 和 lock 不变。
3. 账户登录预检使用同环境、同 bundled executable 的空白有头持久浏览器。临时 profile、启动门、Windows Job/POSIX 进程组隔离、超时与整树清理覆盖普通结果。子进程仅可返回有界数字版本，不输出原始异常。
4. 后台配置验证后、迁移之前，Xvfb 必须通过有界真实连接/存活检查。镜像新增 `x11-utils`；工具缺失、进程死亡或超时以固定错误和非零状态退出。
5. `scripts/check_login_browser.py` 提供不接触凭据的运行 UID 冒烟命令。部署、状态和日志导航已指向修复记录，不修改个人 Compose 设置。
6. 旧合成夹具补齐生产策略需要的工厂/启动结构；新测试执行已验证锁定 factory/main/launcher 方法体和真实入口接线，平台网络工作仍为 stub。
