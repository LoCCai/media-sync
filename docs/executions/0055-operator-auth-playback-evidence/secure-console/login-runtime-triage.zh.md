## 已确认的源码问题

### 执行子进程丢弃共享浏览器缓存配置

`Dockerfile:145-152` 通过 `PLAYWRIGHT_BROWSERS_PATH=/opt/ms-playwright` 安装 bundled Chromium。`checkout.py:210-229` 在运行时/浏览器预检中保留这个设置；但真正登录子进程的 `login_runner.py:73-98,271` 环境白名单不包含它。`bridge.py` 和 `detail_runner.py` 的子进程环境白名单也有同样遗漏。

锁定上游的小红书和抖音持久浏览器启动使用默认 Chromium 查找方式。在只有镜像声明的共享缓存时，丢失设置的子进程会改查默认缓存。这是已确认的代码/配置不匹配，不是对用户当前容器文件系统的直接检查；额外安装过浏览器可能改变现场结果。

### 五个平台指定了镜像未安装的浏览器通道

锁定上游提交 `d6f7c5bb906b6dac40ddf343ef9e26438a3de092` 的持久启动显式传入 `channel="chrome"`：B 站（`core.py:518`）、快手（`:373`）、微博（`:382`）、贴吧（`:631`）、知乎（`:448`）。上述文件位于锁定 checkout 的对应 `media_platform` 目录下。

Dockerfile 安装的是 Playwright Chromium，不是系统 Google Chrome 通道。登录适配器设置 `SAVE_LOGIN_STATE=True`、`ENABLE_CDP_MODE=False`，且没有统一浏览器通道。因此仅补回共享缓存变量，还不能解决这五个平台的启动需求。

### 预检与失败提示掩盖了这些差异

`checkout.py:42-49` 启动默认无头 Chromium。交互扫码登录设置 `HEADLESS=False`（`login_runner.py:639`），使用隔离的持久 profile；无头预检没有验证同一套子进程环境、浏览器通道和显示环境。

`login_runner.py:456-457,575-585` 为保护秘密主动丢弃上游输出，`:831-832` 将一般异常压为 `failed`。现有页面证据无法区分浏览器缺失、显示失败、网络错误或平台拒绝。不要为排错开启原始上游日志，它可能暴露认证材料。

之前 Xvfb 的 `/tmp/.X11-unix` 警告仍需运行态检查，不能直接判为致命错误。`/tmp` tmpfs 和仅无头的预检意味着需要检查显示服务就绪，但它们本身不是失败证明。
