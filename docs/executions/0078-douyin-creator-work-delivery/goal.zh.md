# 目标：以源生游标为依据的抖音创作者作品耐久交付

状态：**仅完成计划**。尚未开始 0078 应用代码、迁移、部署或真人采集。

执行 0078 把 0074（B 站）与 0076（小红书创作者笔记）交付的耐久订阅交付扩展到抖音创作者作品。遵循强制的源码优先姿态：以下每一条推进、结束判定、对账与增量规则，都从钉定 MediaCrawler 的抖音代码与响应形状推导，而非从 Bilibili 或 XHS 实现复制。

上游抖音创作者流程（`media_platform/douyin/core.py`、`client.py`、`exception.py`）定义了本执行依赖的事实：

- 创作者作品在 `/aweme/v1/web/aweme/post/` 上以 `sec_user_id`、固定 `count: 18` 和服务端回显的 `max_cursor` 字符串分页；`max_cursor` 起始为空且必须逐字回放。没有数字页码，也没有总数。
- 停止信号是整数 `has_more`：上游循环只在 `has_more == 1` 时继续。`has_more` 非 `1` 的响应是唯一真实的源末候选。
- `aweme_list` 为空但 `has_more == 1` 的响应让上游循环保持存活却毫无进展；耐久层必须把它记录为独立的停滞原因，而不是循环或宣称结束。
- 每个请求携带经钉定 `douyin.js` 在 Playwright 页上按请求生成的 `a_bogus` 签名；客户端对无法解析的响应体抛 `DataFetchError`，把空或字面 `"blocked"` 的响应体视为 `account blocked`；`IPBlockError` 标记限流。这些是访问受限，绝不是源末。
- 作品身份是 `aweme_id`；创作者身份是从受保护创作者 URL 解析出的 `sec_user_id`。媒体按详情载荷分支：`_extract_note_image_list` 非空即图集（逐图 `NNN.jpeg`），否则 `_extract_video_download_url` 指向单个视频（`video.mp4`）。

目标操作结果：

```text
/crawler/ 原生登录
  -> 把已保存的抖音会话认领到一个 Account
  -> 添加一个创作者作品 Subscription
  -> 有界、max_cursor 跟踪的历史批次
  -> 按作品身份把守的详情抓取与已验证交付
  -> 真实源末之后的头部对账
  -> 面向新作品的增量头部检查
```

## 必需行为

1. **精确订阅所有权。** 每个续传、Job、Run、回执与发布都绑定到一个 Subscription、Account、作者、`posts` 形态的创作者范围以及锁定的 `sec_user_id` 指纹。
2. **逐字游标推进。** `max_cursor` 按服务端回显逐字存储、逐字回放。任何实现都不得解析、重排、再生成或“优化”它。每个单元至多处理一个上游页，并在该单元的 `max_items` 处停止。
3. **四种停止原因，四个固定码。** `has_more_false`（唯一源末候选，连同页证据保留）、`empty_page_stalled`（`aweme_list` 为空而 `has_more == 1`）、`access_restricted`（签名失败、无法解析或被封响应体、`DataFetchError`/`IPBlockError`/封禁态）、`unit_cap_reached`（单元 `max_items` 上限）。只有 `has_more_false` 可后续 qualified 为源末。
4. **身份把守的交付。** 作品详情按 `aweme_id` 从呈现该身份的同一页抓取。一次失败的详情按固定码标记该作品失败，绝不阻塞无关作品；媒体分支（图集 vs 视频）按完整 Content 单元以全有或全无语义发布。
5. **增量之前的头部对账。** 在保留的 `has_more_false` 证据之后，一次有界头部重列必须复现记录的最新边界（最新作品集合相同、游标回显稳定），订阅才可进入增量轮询。漂移保留已交付数据并重开对账；漂移时不发布任何快照完成等价物。
6. **增量运行。** 增量循环重列有界头部页，按稳定 `aweme_id` 去重，只为未见或变化的作品产生工作。无变化循环不写字节、不写 NFO 行。
7. **暂停、删除与恢复。** 暂停态编辑器为策略变更加栅栏；认证过期走既有 waiting-auth 路径；重启、租约丢失与重复执行对同一耐久单元加栅栏。签名或风控受限绝不丢弃耐久游标。

## 验收证据

- 确定性钉定 runner 夹具跨至少三个 `max_cursor` 步分页，记录每次回显，在步间重启后到达真实 `has_more != 1` 结束。
- “空页但 `has_more == 1`”与“被封响应体”两种响应各自记录其独立停止原因并恢复，不伪造源末。
- 源末之后头部漂移（插入一条新作品）重开对账并随后闭合；未变化的头部进入增量模式。
- 一条新作品经抓取一次并发布（图集与视频分支均有夹具覆盖）；无变化重跑为零工作。
- 最终目录/NFO 校验在不配置媒体服务器的情况下通过。
- Linux 镜像、真实抖音登录与真人创作者金丝雀在操作员执行前保持 `NOT_RUN`。

## 明确非目标

- 抖音评论、搜索订阅或任何非创作者范围。
- 把 Bilibili 页码或 XHS token 语义当作抖音形状处理。
- 超出既有暂停/退避策略的风控自动化处理。
- 任何 Emby/Jellyfin 服务器控制。
