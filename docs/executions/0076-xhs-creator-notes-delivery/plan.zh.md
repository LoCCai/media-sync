# 计划

状态：**冻结待后续执行**。本文档本身不授权任何部署、平台请求或驻留进程重启。

## 1. 落笔写状态前先端到端追踪 XHS 路径

- 从已认领的 Account profile 出发，追踪钉定的 XHS 创作者流程：`parse_creator_info_from_url`、`get_creator_info`、`get_notes_by_creator` 分页、每笔记 `xsec_token` 捕获、`get_note_by_id`（含 HTML 回退），直到既有 XHS store/normalizer 形状。
- 复用 0074 的交付骨架（扫描覆盖、多步续传、Job 级摄取、下载器、归档、库写入器），但每个参数都从 XHS 证据重新推导；在验证文档记录钉定 MediaCrawler SHA 与观察到的页形状。
- 明确列出 Bilibili 假设对 XHS 不成立的每个点（不透明游标、token 把守、四种停止原因、封禁态），把每一条写成带测试的契约。

## 2. 耐久游标与停止原因状态

- 按订阅与 `notes` 流逐字持久化不透明游标，旁边是有界计数器与时间戳。仅当现有表无法表达时才做最小迁移扩展；升级/降级必须保留既有部署。
- 记录四种独立停止原因：`has_more_false`、`empty_page_stalled`、`access_restricted`、`unit_cap_reached`。只有 `has_more_false` 可后续 qualified 为源末，且必须保留页证据。
- 每笔记 `xsec_token` 只作为不透明、有界、不可导出的捕获存储，绑定到看到它的 Run；绝不进入 API 载荷或日志。

## 3. 有栅栏单元的有界续传

- 在上一单元的发现与管线回执耐久一致后，每步至多推进一个按页界定的单元；遵守 `max_items`、配置的续传延迟、暂停/删除与认证/退避状态。
- API 精确执行与驻留进程通过 0074/0075 既有耐久所有权栅栏竞争；重复提交复用权威单元。

## 4. 对账与增量头部检查

- 在保留的 `has_more_false` 证据之后，运行一次有界头部重列：必须复现记录边界（最新笔记集合相同、游标形状稳定）才进入增量模式；漂移时保留已交付数据并重开对账。
- 增量循环以新 token 重列有界头部页，按稳定 `note_id` 去重，只为未见或变化的笔记抓详情；token 被拒触发有界重列——绝不视为游标丢失。

## 5. 按完整 Content 单元的交付与发布

- `normal` 与 `video` 笔记映射为 Content，按全有或全无发布；一条失败笔记绝不阻塞无关笔记；部分结果携带精确失败笔记计数与固定码。
- 证明重启与零工作重放保留内容寻址字节与确定性 NFO 输出。

## 6. 操作员界面

- 订阅详情暴露阶段（backfill、reconciling、incremental、blocked）、游标步计数、最近源末/对账证据、下次可运行时间与精确失败笔记计数。不暴露 token、游标本体、主机路径或原始响应。

## 7. 验证序列

1. 游标处理、四种停止原因、token 绑定的详情把守、封闭公共投影的单元测试。
2. 确定性钉定 runner 夹具的集成测试：三个及以上游标步、重启栅栏、历史中途封禁态、源末、头部漂移、进入增量。
3. 经真实下载/归档/NFO 路径的一条新笔记与零工作重放，使用受控夹具。
4. 暂停、删除、认证过期、租约丢失、重复所有权与迁移往返。
5. 完整 Python 与 Web 套件、Ruff、严格 mypy、Web 构建、文档/上游检查、包构建与 `git diff --check`；记录精确的双语结果。
6. Linux 主机构建、真实 XHS 会话认领与真人创作者金丝雀在操作员显式执行前保持 `NOT_RUN`。
