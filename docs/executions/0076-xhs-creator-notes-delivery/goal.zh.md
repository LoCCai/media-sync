# 目标：以源生游标为依据的 XHS 创作者笔记耐久交付

状态：**仅完成计划**。尚未开始 0076 应用代码、迁移、部署或真人采集。

执行 0076 把 0074 为 B 站交付的耐久订阅交付扩展到小红书创作者笔记。遵循强制的源码优先姿态：以下每一条推进、结束判定、对账与增量规则，都从钉定 MediaCrawler 的 XHS 行为与 XHS Web API 形状推导，而非从 B 站实现复制。

上游 XHS 创作者流程（`media_platform/xhs/core.py`、`client.py`）定义了本执行依赖的事实：

- 创作者列表用不透明字符串 `cursor` 分页（空字符串起始）加布尔 `has_more`；每页返回 `notes` 数组。没有数字页码，也没有总数。
- 每条列出的笔记自带短命 `xsec_token`。笔记详情请求（`get_note_by_id`）被该 token 把守；API 详情失败可回退到 HTML 渲染（`get_note_by_id_from_html`）。
- 创作者身份与初始 `xsec_token` 来自创作者 URL 本身（`parse_creator_info_from_url`）；profile 端点需要同一 token。
- 访问可能以封禁/受限状态失败（`IPBlockError`、`PlatformAccessError`），与列表耗尽是两回事。
- 上游循环在 `has_more=false`、空 `notes` 数组、封禁响应中断或达到 `CRAWLER_MAX_NOTES_COUNT` 时停止——四种不同的停止原因，耐久层必须逐一区分。

目标操作结果：

```text
/crawler/ 原生登录
  -> 把已保存的 XHS 会话认领到一个 Account
  -> 添加一个创作者笔记 Subscription
  -> 有界、游标跟踪的历史批次
  -> 按笔记 token 把守的详情抓取与已验证交付
  -> 真实源末之后的头部对账
  -> 面向新笔记的带 token 刷新的增量头部检查
```

## 必需行为

1. **精确订阅所有权。** 每个续传、Job、Run、回执与发布都绑定到一个 Subscription、Account、作者、`notes` 范围以及锁定的创作者 `user_id` 与其 URL 携带的 `xsec_token` 指纹。
2. **不透明游标推进。** 续传游标原样存储、原样回放。任何实现都不得解析、重排、再生成或“优化”它。每个有界步只处理一个上游页，并在该单元的 `max_items` 处停止。
3. **真实的源末证据。** 只有观察到的 `has_more=false`（或一页同时无笔记且游标无前进）连同精确页证据一起记录，才算源末候选。封禁/受限错误、空但 `has_more=true` 的页、以及 `CRAWLER_MAX_NOTES_COUNT` 停止都按各自的停止原因记录，绝不算源末。
4. **token 把守的交付。** 笔记详情使用与呈现该笔记的同一列表页捕获的 `xsec_token` 抓取。token 短命：增量循环必须先重列头部页获取新 token 再抓详情；token 被拒只使该次详情抓取失效（走 HTML 回退，再有界重列），绝不作废耐久游标。
5. **增量之前的头部对账。** 真实源末之后，一次有界头部重列必须复现记录中的最新边界，订阅才可进入增量轮询。漂移（新笔记、头部重排、游标形状变化）保留已交付数据但重开对账；漂移时不发布任何 `baseline_snapshot_complete` 等价物。
6. **增量运行。** 增量循环以新 token 重列有界头部页，按稳定 `note_id` 去重，只为未见或变化的笔记产生工作。无变化循环不写字节、不写 NFO 行。
7. **内容单元可见性。** 笔记类型（`normal`、`video`）按完整 Content 单元发布；一条失败笔记绝不阻塞无关笔记，部分结果如实上报。
8. **暂停、删除与恢复。** 0075 的暂停态编辑器为策略变更加栅栏；认证过期走既有 waiting-auth 路径；重启、租约丢失与重复执行对同一耐久单元加栅栏。

## 验收证据

- 确定性钉定 runner 夹具跨至少三个游标步分页，记录每个游标，在步间重启后到达真实 `has_more=false` 结束。
- 历史中途的封禁态响应记录其独立停止原因并恢复，不伪造源末。
- 源末之后头部漂移（插入一条新笔记）重开对账并随后闭合；未变化的头部进入增量模式。
- 一条新笔记经其新 token 抓取一次并发布；无变化重跑为零工作。
- 最终目录/NFO 校验在不配置媒体服务器的情况下通过。
- Linux 镜像、真实 XHS 登录与真人创作者金丝雀在操作员执行前保持 `NOT_RUN`。

## 明确非目标

- XHS 评论、搜索流订阅或任何非创作者范围。
- 把其他平台的分页当作 XHS 形状处理。
- 超出既有暂停/退避策略的封禁自动化处理。
- 任何 Emby/Jellyfin 服务器控制。
