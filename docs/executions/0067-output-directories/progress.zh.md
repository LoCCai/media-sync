# 推进结果

应用修改前冻结计划。核查确认输出Job绑定哈希发布作用域，但旧ExportRecord相对路径本身不能还原绝对根；新配置必须保留旧根并保护既有发布。无需更改私有归档路径。

## 已实现

- 新增0012迁移、共享输出策略与不可变作者根绑定；GET/预览不初始化数据库、不创建目录。保存使用CAS，首次绑定与保存受同一数据库锁保护。
- 新库默认总目录/平台/作者，既有库保留平铺。旧发布已有scope与环境根不匹配时拒绝初始化，不能猜旧路径；需先恢复原环境目录。已有输出/绑定的平台变根返回409，未使用平台仍可编辑。
- 设置页可编辑总根、七平台覆盖，显示当前/预览生效路径及保护标记；修改后重新预览、冲突保留草稿、不自动重试。只接受容器内原生绝对本地目录，拒绝私有/系统/重叠目录及现有链接祖先。
- API、CLI、已有或全新supervisor worker、手动兼容目录写入均读同一数据库配置；下载前绑定输出根。私有归档/凭据/任务不搬动，正常流水线不要求连接媒体服务器。
- 本地媒体树按作者选择exporter并保留分页隔离。可选媒体服务器仍是原单根固定映射，新根不匹配时拒绝远程核验，不猜映射。

## 复核修正

独立复核发现并补上两项：系统安装目录未被拒绝；旧发布scope不匹配时可能绑定到新的环境根。测试构造seam、迁移head/21表断言与API类型/格式问题均保留在验证记录，不把修正前失败算PASS。

## 用户追加：扫码仍失败与下一版日志中心

按computer-use技能指引使用浏览器只读核查账户和微博操作详情，未触发预检/扫码/采集/下载。2026-09-06页面保存结果：Bili/XHS/Zhihu已认证，DY/KS/贴吧/微博均为上游浏览器操作超时。微博操作前缀80789097，12:15:18→12:16:01，43秒；摘要runner_status=upstream_browser_timeout，事件仅authenticating，没有导航/点击/二维码/确认子阶段。

源码确认login_runner子进程stderr和上游fd1/2被丢弃，返回协议只保留状态，当前support_bundle是聚合摘要，不是日志存档。现有信息不能恢复具体卡点，也不能判断Cookie错或网络故障。下版优先[日志中心及登录阶段诊断](next-delivery.zh.md)，不再以固定错误分类上线代替实际登录验收。

## 待实现与边界

日志中心尚未实现；剩余扫码故障仍未修复。本轮只读线上检查，不部署、不恢复supervisor、不改认证。显式旧媒体迁移、完整历史转增量语义、精确订阅按钮到真实下载验收仍待推进；其它平台原目标不变。路径预检不等于挂载可写、也不证明消除了恶意并发更换祖先的全部TOCTOU风险。
