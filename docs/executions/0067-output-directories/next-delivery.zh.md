# 下一版优先交付：日志中心与扫码可诊断性

状态：用户在0067开发中追加，尚未实现。优先于继续扩展头像；原订阅→历史→下载→增量主线不变。

## 必达结果

1. 一个日志中心统一查看API、登录/资料/采集子进程、scheduler/supervisor、下载/归档/目录写入各组件记录；按时间、平台、账户、级别、operation/session/job/run关联筛选，任务详情可直达，不只列错误次数。
2. 日志持久化到私有挂载目录，使用JSONL滚动分片。明确大小/时间切片、保留时长及总容量上限；API与supervisor使用进程独立片段或单一收集器，禁止多个进程争抢同一个RotatingFileHandler。默认值在实现计划冻结时确定，设置可查；轮转/截断/丢失必须可见，不能把磁盘写满。
3. 登录记录启动浏览器、打开平台、显示登录入口、取得二维码、等待扫码、确认本人会话、保存等可观测阶段及耗时；记录失败动作类别、经过约束的上游模块/函数/行号、异常类型、允许的主机/路由模板、响应状态。没有证据的阶段标unknown，不以“超时”猜风控或网络。
4. 不能简单取消静音后把所有原始stdout/stderr写盘。采用有界、版本化诊断旁路，严格白名单字段；不放宽原结果帧，不改锁定上游文件。Cookie/Authorization/令牌/二维码/签名查询、响应正文、locals和原始异常字符串不进入普通日志。未知文本只保留固定类别和丢弃计数，必要的深诊断另行定义脱敏结构。
5. 一键生成按本次operation关联的诊断包，包含应用版本/上游锁、事件阶段和安全错误栈、组件片段、保留覆盖范围。只供用户主动下载，不自动发送第三方。普通用户看到失败位置/下一步，开发者可展开精确证据。

## 验证门槛

- 分别注入导航、登录入口、二维码获取、确认超时和进程退出，证明不同阶段从子进程→持久片→API→页面→下载诊断包仍可区分。
- 长日志、无换行/多字节分片、截断、重复事件、两进程并写、轮转时读取、重启、磁盘满/权限拒绝有确定结果，不阻塞调度；丢失/过期明确展示。
- Cookie/令牌/二维码/签名URL/嵌套异常秘密哨兵扫描所有日志、数据库、诊断包及页面，包含超限/异常路径。拒绝任意文件路径读取、遍历、symlink/reparse、未认证下载；分页与响应有界。
- 保存现有已认证账户，不自动重试。部署新诊断版后，按用户授权对失败平台各做一次可控复测，逐个留下原因/修复/验收，不把离线测试当真人成功。
