# 目标：B 站投稿耐久回填转增量本地交付

状态：**本地实现完成**，实现提交为 `9c81c4b`。尚未开始部署或真人 B 站验收。

执行 0074 让 0073 原生 MediaCrawler 会话认领后的一个精确 B 站 `uploads` 订阅真正可用。继续复用既有 Account profile、MediaCrawler runner、scheduler、Job 级摄取、下载器、SHA-256 归档及 Emby/Jellyfin 兼容目录/NFO writer；没有增加登录页、爬虫、下载器、调度器或“导出”产品。

目标操作结果保持直接：

```text
/crawler/ 原生登录
  -> 把保存会话认领给一个 B 站 Account
  -> 添加一个投稿订阅
  -> 按节奏执行有界历史批次
  -> 把已验证媒体写入配置的媒体库根
  -> 到达源末尾后重新对账当前头部
  -> 定期有界检查新投稿
```

Emby/Jellyfin API 连接继续为可选项。耐久产品结果是配置目录中的文件树及 NFO/sidecar，其他容器或媒体服务器可直接扫描。

## 必须实现的行为

1. **精确订阅所有权。** 每个 continuation、Job、Run、receipt 与 publication 必须绑定同一个 Subscription、Account、作者、`uploads` scope 和锁定上游身份；绝不消费其他订阅队列，也不读取共享 `/data/mediacrawler/webui-output`。
2. **有界历史批次。** 每个发现单元最多处理 `min(max_items, 30)` 个已验证投稿详情，并保留现有请求次数上限。更多历史由后续耐久单元继续，不允许在一个进程中无限循环。
3. **按节奏续跑。** 成功批次若证明仍有历史，只能在配置的续跑间隔之后安排下一单元。认证、验证、限流和暂时失败继续使用现有暂停/退避策略；不绕过验证、不轮换凭据或代理。
4. **真实基线状态。** 仅到达历史源末尾不能算完成，还要针对保存边界做一次有界头部对账。只有稳定结果才能发布 `baseline_snapshot_complete`；它表示某一时点的快照已对账，不表示平台历史永久完整。
5. **安全失效。** Account 认证 revision、作者身份、Subscription scope、相关策略 generation 或锁定上游身份变化时，基线必须失效并重新走有界对账，不能静默复用不兼容 continuation。
6. **增量运行。** 基线完成后，普通定时周期以重叠窗口和稳定 ID 去重执行有界头部检查。后来新增一条投稿时只生成缺失的下载/归档/发布工作；零工作周期不改写已有字节，也不重复 NFO 条目。
7. **按内容单元可见。** 一条失败或不支持的旧作品不能长期隐藏其他已验证作品。发布以完整 Content 为单位：同一多 P 视频或图集内部仍全有或全无，其他完整 Content 可以发布；总体结果必须如实报告部分失败。
8. **暂停、删除与恢复。** 暂停阻止新的续跑单元；移除阻止新工作但保留历史/媒体；认证过期让精确工作进入既有 waiting-auth。重启、lease 丢失及 supervisor/API 重复尝试必须恢复或隔离同一耐久单元，不能重复下载或发布。
9. **用户可见证据。** 订阅详情显示有界阶段（`backfill`、`reconciling`、`incremental`、`blocked`）、批次数量、最近已证明的源末尾/对账证据、下次可运行时间和精确失败 Content 数；不暴露 Cookie、locator、宿主路径或上游原始响应。

## 验收证据

- 至少 65 条普通投稿的确定性锁定 runner fixture 跨越至少三个批次，在 discovery、pipeline 和状态发布附近重启后仍可恢复，到达源末尾、完成头部对账并进入增量模式。
- 回填期间出现分页漂移或新头部作品时必须重新对账，不能错误声明完成。
- 之后新增一条投稿只能下载并发布一次；内容不变的重跑必须是零工作。
- 一条无关旧作品失败时，另外两条有效作品仍能发布；不完整多分段内容绝不部分发布。
- 针对精确订阅覆盖暂停、移除、认证过期、lease 丢失、重复执行和续跑间隔。
- 未配置媒体服务器 provider 时，最终目录树/NFO 验证仍通过。
- 当前 Linux 镜像、真人 B 站登录/profile 认领、UID `252671524`、CDN 字节、宿主最终目录及之后一次真人增量周期，在操作者明确执行并记录金丝雀前继续为 `NOT_RUN`。

## 明确不做

- B 站动态、番剧、直播、付费媒体、字幕或弹幕。
- 其他六个平台；它们各自需要分页及源末尾证据。
- 自动导入交互式爬虫控制台输出。
- 自动绕过风控或轮换凭据/代理。
- 强制连接或自动控制 Emby/Jellyfin 服务器。
- 通用订阅策略编辑器。它是本交付之后的 UI 候选，必须使用暂停态和 schedule revision fencing。
