# 冻结实施顺序

先提交本计划再实施。按顺序交付四项需求的实际 API/UI 与测试；四项都完成并按各自边界验证前，不把本执行标为完成。

1. 在 Library/Settings 与部署文档区分本地兼容目录输出和可选媒体服务器联动。保留既有导出器、归档校验、鉴权及可选服务器完整配置校验。验证未配置 connector 也能导出；本地文件导出不要求远程播放资格。
2. 增加 nullable deleted_at 墓碑和新迁移，实现可恢复的订阅删除；保留 Author/Content/Asset/Run/Job/来源/历史和磁盘字节。默认列表隐藏已删除项，提供明确请求的已删除列表/历史以及恢复同一 ID 和 checkpoint 的入口，恢复后先暂停。保留账户/作者唯一键。添加流程不静默重建、覆盖选项或重启旧订阅：返回固定已删除冲突并引导恢复。
3. 删除必须原子、幂等。有 claimed/running 执行或相关活动 Operation 时固定冲突且不产生部分修改；仅历史 Run=running 不代表正在执行。删除事务中取消符合条件的未开始 queued/wait/retry 采集/流水线 Job，保留历史，不宣称完成进程清理。调度/领取/恢复/立即运行、流水线创建/执行与凭据刷新来源选择均拒绝墓碑订阅；竞争测试须证明删除后不再执行。显式恢复保持暂停，不恢复已取消 Job。API/CLI 共用服务；UI 确认准确说明保留和取消范围。
4. Jobs 优先显示业务状态、下一步和单独的开发者详情。增加鉴权、精确 Job 绑定的诊断报告，仅包括固定版本/数据库版本、Job/Run 状态/错误/时间及有界关联 Operation 证据。保留未知和状态不一致，不猜根因，不输出原始异常/SQL、Cookie、profile/宿主路径、请求 payload、签名 URL 或任意字段迭代。既有聚合支持包不改；明确点击后才复制/下载，失败不反射原始错误。
5. 随后完成自动创作者查询：独立有界单作者资料请求，先 Bili 再逐平台落实合同，不以内容采集代替查询。绑定账户/平台/作者和请求代际，验证远端身份/昵称/头像，单独保留用户别名，并防止普通入库清空已有资料。保留 CSP，使用身份绑定的安全同源头像而非任意 URL 代理。实施前以子计划冻结涉及子进程/协议/存储的精确合同，不能因为上游方法存在就称已通过验证。实现前明确当前预览只是本地校验，不冒称自动获取。
6. 保存双语进度/验证，运行专项和更广 API/repository/scheduler/pipeline/migration/Web 测试、独立复核、文档/静态/上游门禁，中英双语提交及推送核验。本编码增量不授权生产部署/删除、登录、重试、下载、导出或恢复 supervisor。

此前 B 站 cap 核查发现正确性依赖：直接最新 N 条加既有最大时间水位，会永久跳过未见历史/新增。尚未修改任何 cap 或水位代码；本可用性优先项后以持久化有界覆盖/续扫推进，不偷偷替换成仅最新 N 条。Cookie 登录与其他真人/归档/播放门仍是必做后续。
