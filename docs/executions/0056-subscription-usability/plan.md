Commit this plan before implementation. Deliver the four requests in order with working API/UI paths and tests; do not mark the execution complete until all four are implemented and qualified to their documented scope.

1. Separate local compatible-directory output from optional media-server linkage in Library/Settings and deployment docs. Preserve the existing exporter, archive checks, authentication and all-or-none optional server configuration. Test export without a configured connector; file export does not require remote playback qualification.
2. Implement reversible subscription removal with a nullable deleted_at tombstone and a new migration. Keep Author/Content/Asset/Run/Job/source/history and filesystem bytes. Hide removed subscriptions from the default list; retain an explicitly requested removed list/history and provide explicit restore of the same ID and checkpoint, initially paused. Keep the existing account/author unique key. Do not silently re-create, overwrite options or restart an old subscription from the add workflow: return a fixed removed-subscription conflict and offer restore.
3. Removal must be atomic and idempotent. Refuse in-flight claimed/running work or relevant active Operations with a fixed conflict and no partial changes; stale Run=running alone is not evidence of live execution. Cancel eligible unstarted queued/wait/retry sync/pipeline jobs within the removal transaction, without deleting history or claiming process cleanup. Reject removed subscriptions in scheduling/claim/resume/run-now, pipeline creation/execution and credential refresh-source selection; race tests must prove no post-removal work. Restore is explicit, paused, and never resumes cancelled Jobs. API and CLI share the service; UI confirmation states exactly what is retained/cancelled.
4. Improve Jobs around business state, next action and an explicit developer-details section. Add an authenticated, exact-Job diagnostic report with closed version/schema, Job/Run status/error/timing and bounded correlated Operation evidence. Preserve unknowns and mismatches; no guessed root cause, raw exception/SQL, cookies, profile/host paths, request payloads, signed URLs or arbitrary field iteration. Keep the existing aggregate support bundle unchanged. Copy/download only after an explicit click; a failed report must not reflect raw errors.
5. Next complete automatic creator lookup: independent bounded single-profile request, starting with Bili then implementing each platform contract; do not use a content crawl for lookup. Bind account/platform/creator and request generation, validate remote identity/name/avatar, retain user alias separately, and prevent ordinary ingestion from erasing established profile fields. Keep CSP and use identity-bound same-origin safe avatars, not an arbitrary URL proxy. Freeze that sensitive child/protocol/storage contract in a child plan before implementation; no existing method is assumed qualified merely because upstream exposes it. Until implemented, label current preview as local validation and do not claim automatic lookup.
