# Execution 0009 goal

- Status: Function-first MVP implemented locally; live qualification and hardening deferred
- Started: 2026-08-30 20:38 +08:00
- Predecessor: Execution 0008 implementation commit `3889539`
- Network boundary: offline fake pinned-upstream modules, local helper processes and mock HTTP only
- Checkpoint truth: migration/provenance, terminal cleanup, bounded detail refresh, CLI wiring and one-time 401/403 renewal pass offline focused gates

## Outcome

Deliver an explicit, default-off MediaCrawler signed-locator refresh path for a manually selected existing Asset, while binding refresh authority to the exact Subscription and Account that observed the current asset identity. The refreshed URL may exist only in a private child result channel, trusted-parent memory and the `SafeHttpClient` request boundary; it must never become durable state or operator output. Close the successful/recovered MediaCrawler attempt-artifact boundary by removing or securely isolating the exact source root before outward success.

## Function-first completion decision

The local MVP is accepted against the following implemented boundary. The longer acceptance matrix below remains the original hardening target and is not a claim that every adversarial, retained-artifact or live-account row has run.

- `media-sync asset download` remains default-off for adapter refresh and requires both `--enable-mediacrawler` and `--accept-mediacrawler-license`. An optional `--subscription-id` resolves multiple current eligible observations.
- The lazy runtime binds the selected Asset to its current Content, Author, Subscription and Account, resolves Cookie or saved-session context only when network refresh is actually required, and invokes the pinned MediaCrawler detail child. Verified and prepared-recovery paths can finish without invoking refresh.
- Offline supported shapes are XHS image/video, Douyin image/video/audio/cover, Kuaishou video/cover and Bilibili cover. XHS currently requires an ephemeral `--xhs-detail-reference-ref` containing the exact note URL with `xsec_token` and `xsec_source`; automatic creator-feed lookup remains deferred.
- The detail result is bounded, returned in memory, normalized with the ingestion normalizer, selected by exact content/kind/position/query-free source hint and deleted with its UUID attempt root before return. The signed URL is never written back to SQLite.
- Adapter refresh retries resolution once after HTTP 401/403. A second authorization failure returns retryable `locator_refresh_auth_expired`; direct locators never refresh.
- Automatic downstream execution belongs to execution 0010. Live platform, CDN and Emby/Jellyfin qualification, automatic XHS detail bootstrap, exhaustive cancellation/security matrices, retained sentinel, full build/wheel and public/HA operation remain explicit follow-up work.

## Acceptance criteria

1. All implementation verification is offline. Tests may use repository-owned helper processes, fake pinned-upstream module shapes and mock HTTP transports, but no browser session connected to a real platform, real credential, platform/CDN endpoint, Emby/Jellyfin server or Git remote.
2. Alembic revision `0005_asset_refresh_sources` adds a many-to-many `asset_refresh_sources` observation table. A source binds `asset_id + subscription_id` to the observed semantic and locator fingerprints, records generation only for audit, distinguishes exact ingestion from conservative legacy inference, and optionally points to the latest observing SyncRun by monotonic `(created_at, id)` order without storing any credential, creator secret, signed URL or runtime path. Replaying an older run never regresses `last_run_id` or timestamps.
3. Source eligibility requires the current Asset semantic and locator fingerprints, stable `adapter_refresh` identity, Content/Author/Subscription relation, Account platform/adapter and the observation to agree. Asset generation remains the download Job fence but is not source eligibility: `reset_verified_archive()` may increment generation without invalidating an otherwise identical observation. Any persisted semantic **or locator** fingerprint replacement starts a new generation and resets downloader state, so an immutable Job source can never poison the same generation; signed-query rotation is excluded because it is never persisted.
4. Migration backfill creates a source only when the exact `Asset.platform == Content.platform == Author.platform == Account.platform`, Subscription-author, MediaCrawler adapter, parsed-locator adapter and recomputed stable-asset-key chain agrees and the current Content author has exactly one such Subscription. Zero or multiple candidates, any mismatch, a malformed locator or a corrupted stable key remains unbound. Downgrade removes only the new observation table; upgrade/downgrade/re-upgrade preserves existing download and Emby recovery identities.
5. MediaCrawler ingestion upserts the observation in the same guarded transaction as Asset upsert and checkpoint advancement, using the exact subscription/run. It proves that `last_run_id` belongs to that Subscription and that the full author/platform/account chain agrees; any mismatch rolls back the observation, Asset change and checkpoint. Replay is idempotent; a semantic- or locator-fingerprint replacement advances generation, updates the observing source and leaves other stale observations as ineligible audit rows.
6. Manual CLI refresh requires `--enable-mediacrawler` and `--accept-mediacrawler-license`, with optional `--subscription-id`. With no same-generation Job, zero eligible sources return `locator_refresh_source_unavailable`, one is selected and multiple return `locator_refresh_source_ambiguous`. With an existing same-generation Job, its closed bound source is authoritative and must still be eligible/current; an optional explicit source must equal it, while unrelated newly eligible sources neither create ambiguity nor permit rebind. Missing/open/corrupt/ineligible binding or a different explicit source returns `locator_refresh_source_mismatch`. All preflight failures make zero SQLite changes.
7. Source selection and download begin revalidate generation, fingerprints, recomputed stable asset key, Content/Author/Subscription/Account relations and the exact selected or Job-bound source in one transaction. An `asset_download` Job keeps the existing `asset_id:generation` natural key, fills its existing subscription/account/platform scope, keeps `run_id = NULL`, and stores an immutable closed non-secret key of IDs/platform plus semantic/locator fingerprints. Observation kind is provenance audit only and never part of Job source equality, so `legacy_unique_inferred -> ingested` cannot strand an existing Job. `AssetRefreshSource.last_run_id` remains observation audit only and is never a predecessor or dependency.
8. The hard order for every manual invocation is enable/license -> read-only unresolved-account block fence -> read-only classification of already-verified, exact prepared recovery or network-bearing work. Inspection itself is zero-mutation; a valid already-verified archive returns without Job/Asset mutation, while exact prepared recovery may perform only CAS/lease takeover and success finalization of the already-bound generation. Neither path requires an eligible source, profile, credential, child or HTTP. Network-bearing work validates source/runtime/reference identities, then acquires the same account/profile security lock used by every cleanup-block writer. Inside that lock but outside SQLite it rechecks the filesystem block and resolves Cookie/creator secrets; a short transaction then rechecks only frozen database Account (`id`, platform, adapter, login method, credential-ref identity, profile identity, auth status), Subscription (`id`, account, author, enabled and canonical closed-policy identity), Author (platform/remote ID), observation and Asset/Job identities before claim. The lock remains held through child-tree join, safe-download finalization and any cleanup. A block or mismatch fails closed before SecretResolver/claim, run attach, bridge preparation, child spawn or HTTP as applicable; no filesystem I/O occurs inside SQLite and no closed credential identity is persisted in Job payload or logs.
9. The refresh port receives a frozen Asset and source context, not only the one-way locator key. A dedicated supervised detail-only child imports the pinned external runtime, uses the exact account/profile lock, inherits parent-death/cancellation/process-tree fencing and returns one bounded strict frame over a dedicated inherited OS pipe/handle that is distinct from fd 1/2. Before any upstream import, ordinary stdout and stderr are redirected to null at OS level; the parent concurrently drains the bounded result pipe to EOF and closes every inherited handle. The URL never enters argv, the ordinary environment, disk, JSONL, stdout/stderr relay or an exception message.
10. The private frame rejects duplicate keys, unknown fields, multiple frames, trailing content, invalid identity echoes, overflow and malformed/truncated data. Process exit status, exactly one frame, EOF and handle closure must agree; stdout/stderr injection cannot contaminate the frame or operator sinks. A watchdog timeout maps to retryable `locator_refresh_temporary`; any nonzero exit, missing frame, exit/frame disagreement or invalid frame maps to terminal `locator_refresh_result_invalid`; cancellation remains the existing cancellation outcome. Parent results and errors contain only fixed allowlisted status codes and no child-controlled text.
11. Offline platform shape support is limited to eligible current Assets with an exact stored query-free source hint: XHS image/video, Douyin image/video/audio/cover, Kuaishou video/cover and Bilibili cover. XHS bootstraps its creator feed only from the exact Subscription's freshly resolved `creator_input.secret_ref`: strict parsing must prove an HTTPS Xiaohongshu creator URL, `user_id == Author.remote_id`, and non-empty `xsec_token`/`xsec_source`; nothing is reconstructed from Asset/raw/position. It searches at most four 30-item pages (120 candidates) inside a 120-second refresh-child watchdog before detail. Missing/malformed/mismatched authority returns `locator_refresh_configuration_invalid`; expired authority returns `locator_refresh_auth_expired`; no target within 120 candidates returns `locator_refresh_asset_not_found`; malformed/repeating pagination returns `locator_refresh_schema_changed`; watchdog expiry returns `locator_refresh_temporary`. Bilibili does not call `playurl`. Weibo, Tieba and Zhihu return fixed unsupported codes without spawn because they currently normalize no Asset.
12. The trusted child validates exact platform/content/kind/position/remote request identity, applies current normalization semantics and proves that the required query-free source hint selects exactly one candidate before emitting success. The success frame echoes only a fingerprint covering the full frozen request plus the URL; the parent validates that fingerprint, the closed hint contract and URL syntax, not an unverifiable child candidate echo. The current synthetic `Asset.remote_id` is not a platform variant identity: a missing hint or multiple same-kind/non-unique candidates fail closed rather than trusting position or upstream list order. A mismatch returns `locator_refresh_asset_mismatch` and never downloads into the current generation.
13. Adapter-refresh download may re-resolve at most once, and only after HTTP 401/403. A second auth failure uses a fixed refresh-specific retryable code. Direct locators never re-resolve. Resumable metadata continues to store only the persistent locator fingerprint, never the resolved URL/query or platform credentials; no Cookie/Origin/Referer header is forwarded to the CDN redirect chain.
14. Fresh success, recovered success and already-succeeded restart all derive and clean the exact source attempt before outward success. Recovered metadata is closed and must prove the source attempt/execution/run identity, including the deterministic execution UUID. No path may be derived from untrusted open JSON fields; a successor/current attempt root and persistent browser profile are never deleted.
15. Terminal cleanup is cancellation-shielded, repeated-cancellation-safe and concurrency-idempotent. `ABSENT`/`REMOVED` finish cleanly; `QUARANTINED` is a secured but explicitly credential-bearing isolation boundary; `UNRESOLVED` attempts a fixed redacted durable block and hard-fences the account. Once Run/checkpoint/content success is committed, malformed in-memory results, authoritative readback mismatch/error, every cleanup state, cancellation and lease loss must preserve that database truth and return only a fixed control outcome; none may call failure mutation, re-ingest or rewrite a succeeded SyncRun. Restart performs exact cleanup only. A concurrent `FileNotFoundError` after another worker secured the same root is a safe absent/removed outcome, not a false permanent block.
16. Generated signed sentinels are proved to cross the private frame and mock HTTP request. Separate dynamic sentinels are injected into fresh- and recovered-success JSONL source roots after collection, proved present before cleanup, and proved removed or secured at the exact source identity; already-succeeded restart proves the same exact source identity. All sentinels then have exact zero matches in retained safe runtime trees, download work/archive/sidecars, every SQLite text/JSON value and database/WAL/SHM file, manifest/receipt/JSONL, Job/Asset state, CLI/captured output, JUnit and exception/result `str`/`repr`. Quarantine, unresolved roots and browser profiles remain separately enumerated credential-bearing negative boundaries.
17. Ruff, format, strict mypy, the full branch-aware suite, focused refresh/cleanup/platform/migration gates, build, packaged migrations/resources, documentation, upstream pins, patch checks, ignored/untracked-runtime checks and a fresh retained-artifact sentinel all pass with exact recorded results.

## Truth boundary and non-goals

- This planning commit changes no runtime capability. Signed-locator refresh and successful/recovery terminal cleanup remain `NOT_RUN` until the implementation commit records exact evidence.
- Automatic durable `sync → download → Emby` planning remains execution 0010. Execution 0009 neither creates downstream DAG Jobs nor changes scheduler fan-out/fan-in semantics.
- Offline fake-detail support is not live qualification. QR/Cookie/saved-session login, creator traffic, signed refresh, CDN retrieval and Emby/Jellyfin scan/playback remain `NOT_RUN` for all seven real platforms until user-authorized environments are supplied. Phone login remains unsupported.
- QR refresh remains a fixed user-interaction-required result; execution 0009 implements non-interactive Cookie and saved-session paths only. Platform API credentials/headers stay inside the child and are never forwarded to CDN redirects.
- Bilibili playable video/DASH/multi-part/subtitle/danmaku, Weibo/Tieba/Zhihu Asset discovery, platform derivatives, per-request upstream spacing, REST, resident supervision, Docker, public deployment and HA/PostgreSQL remain unimplemented or deferred.
- The execution 0008 safe failure-artifact result remains valid. Successful sealed v3 output continues to be an explicit credential-bearing temporary boundary until execution 0009 implementation and its retained-artifact gate pass.
- An `UNRESOLVED` cleanup account block is persistent security state. Execution 0009 does not silently clear or bypass it; operator repair/acknowledgement remains a later explicit control surface.
