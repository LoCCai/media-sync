## Outcome / 结果目标

Deliver an explicit, default-off MediaCrawler signed-locator refresh path for a manually selected existing Asset, while binding refresh authority to the exact Subscription and Account that observed the current asset identity. The refreshed URL may exist only in a private child result channel, trusted-parent memory and the `SafeHttpClient` request boundary; it must never become durable state or operator output. Close the successful/recovered MediaCrawler attempt-artifact boundary by removing or securely isolating the exact source root before outward success.

为手工选择的既有 Asset 交付显式启用、默认关闭的 MediaCrawler 签名 locator 刷新路径，同时把刷新权限绑定到观察到当前资产身份的精确 Subscription 与 Account。刷新 URL 只能存在于私有 child 结果通道、可信父进程内存及 `SafeHttpClient` 请求边界，绝不能进入持久状态或运维输出。在向外返回成功前删除或安全隔离精确来源根，关闭 MediaCrawler 成功/恢复 attempt 产物边界。

Replaying an older run never regresses `last_run_id` or timestamps.
3. Source eligibility requires the current Asset semantic and locator fingerprints, stable `adapter_refresh` identity, Content/Author/Subscription relation, Account platform/adapter and the observation to agree. Asset generation remains the download Job fence but is not source eligibility: `reset_verified_archive()` may increment generation without invalidating an otherwise identical observation. Any persisted semantic **or locator** fingerprint replacement starts a new generation and resets downloader state, so an immutable Job source can never poison the same generation; signed-query rotation is excluded because it is never persisted.
4. Migration backfill creates a source only when the exact `Asset.platform == Content.platform == Author.platform == Account.platform`, Subscription-author, MediaCrawler adapter, parsed-locator adapter and recomputed stable-asset-key chain agrees and the current Content author has exactly one such Subscription. Zero or multiple candidates, any mismatch, a malformed locator or a corrupted stable key remains unbound. Downgrade removes only the new observation table; upgrade/downgrade/re-upgrade preserves existing download and Emby recovery identities.
5. MediaCrawler ingestion upserts the observation in the same guarded transaction as Asset upsert and checkpoint advancement, using the exact subscription/run. It proves that `last_run_id` belongs to that Subscription and that the full author/platform/account chain agrees; any mismatch rolls back the observation, Asset change and checkpoint. Replay is idempotent; a semantic- or locator-fingerprint replacement advances generation, updates the observing source and leaves other stale observations as ineligible audit rows.
6. Manual CLI refresh requires `--enable-mediacrawler` and `--accept-mediacrawler-license`, with optional `--subscription-id`. With no same-generation Job, zero eligible sources return `locator_refresh_source_unavailable`, one is selected and multiple return `locator_refresh_source_ambiguous`. With an existing same-generation Job, its closed bound source is authoritative and must still be eligible/current; an optional explicit source must equal it, while unrelated newly eligible sources neither create ambiguity nor permit rebind. Missing/open/corrupt/ineligible binding or a different explicit source returns `locator_refresh_source_mismatch`. All preflight failures make zero SQLite changes.
7. Source selection and download begin revalidate generation, fingerprints, recomputed stable asset key, Content/Author/Subscription/Account relations and the exact selected or Job-bound source in one transaction. An `asset_download` Job keeps the existing `asset_id:generation` natural key, fills its existing subscription/account/platform scope, keeps `run_id = NULL`, and stores an immutable closed non-secret key of IDs/platform plus semantic/locator fingerprints. Observation kind is provenance audit only and never part of Job source equality, so `legacy_unique_inferred -> ingested` cannot strand an existing Job. `AssetRefreshSource.last_run_id` remains observation audit only and is never a predecessor or dependency.
8. The hard order for every manual invocation is enable/license -> read-only unresolved-account block fence -> read-only classification of already-verified, exact prepared recovery or network-bearing work. Inspection itself is zero-mutation; a valid already-verified archive returns without Job/Asset mutation, while exact prepared recovery may perform only CAS/lease takeover and success finalization of the already-bound generation. Neither path requires an eligible source, profile, credential, child or HTTP. Network-bearing work validates source/runtime/reference identities, then acquires the same account/profile security lock used by every cleanup-block writer. Inside that lock but outside SQLite it rechecks the filesystem block and resolves Cookie/creator secrets; a short transaction then rechecks only frozen database Account (`id`, platform, adapter, login method, credential-ref identity, profile identity, auth status), Subscription (`id`, account, author, enabled and canonical closed-policy identity), Author (platform/remote ID), observation and Asset/Job identities before claim. The lock remains held through child-tree join, safe-download finalization and any cleanup. A block or mismatch fails closed before SecretResolver/claim, run attach, bridge preparation, child spawn or HTTP as applicable; no filesystem I/O occurs inside SQLite and no closed credential identity is persisted in Job payload or logs.
9. The refresh port receives a frozen Asset and source context, not only the one-way locator key. A dedicated supervised detail-only child imports the pinned external runtime, uses the exact account/profile lock, inherits parent-death/cancellation/process-tree fencing and returns one bounded strict frame over a dedicated inherited OS pipe/handle that is distinct from fd 1/2. Before any upstream import, ordinary stdout and stderr are redirected to null at OS level; the parent concurrently drains the bounded result pipe to EOF and closes every inherited handle. The URL never enters argv, the ordinary environment, disk, JSONL, stdout/stderr relay or an exception message.
10. The private frame rejects duplicate keys, unknown fields, multiple frames, trailing content, invalid identity echoes, overflow and malformed/truncated data. Process exit status, exactly one frame, EOF and handle closure must agree; stdout/stderr injection cannot contaminate the frame or operator sinks. A watchdog timeout maps to retryable `locator_refresh_temporary`; any nonzero exit, missing frame, exit/frame disagreement or invalid frame maps to terminal `locator_refresh_result_invalid`; cancellation remains the existing cancellation outcome. Parent results and errors contain only fixed allowlisted status codes and no child-controlled text.
