# Frozen plan

1. Introduce a closed Cookie-header parser: bounded ASCII input (16 KiB, at most 128 unique pairs), split each pair at its first equals sign, reject duplicates/control characters/attributes/URLs/unsupported JSON shapes. Secret wrappers are repr-safe. Do not reuse the pinned parser that silently discards values containing equals signs. The input is a request Cookie header, not a Set-Cookie header or browser JSON export.
2. Add a standalone supervised validator, fixed remote URLs only, no redirects/proxies/arbitrary destinations, bounded JSON and wall deadline including signing/runtime verification. Bili uses nav, WB m.weibo.cn config, XHS selfinfo with locked pure signing, Zhihu me with locked offline JS signing. Require explicit authenticated/self-identity response shapes; HTTP 200, public data or local markers alone are not success. No crawler.start, QR, feed, author-history or shared browser-profile mutation. Unsupported DY/KS/Tieba returns a fixed code, preserving the full future target.
3. Store validated candidates as immutable `managed:UUID` files under state_dir/credentials, separate from read-only /run/secrets. Confined no-symlink regular-file access, bounded reads, private directories/files and atomic creation; retain previous versions. Extend explicit runtime resolvers so subsequent processes resolve the same credential. Never store Cookie text in Account/Operation/Event/logs or public results.
4. Add Operation kind account-cookie-login and migration0011 extending its CHECK without losing FK children/history. Do not create or rewrite QR LoginSession records. Account CAS binds backend/platform/expected auth_revision and original auth identity, rejects active QR ownership, and updates credential_ref/login_method/auth status/revision only on remote success. Extend the short DB-only commit_success fence to atomically update Account and terminal Operation. Failed/cancelled/expired/late attempts retain the old account. Never delete a candidate file after an ambiguous commit; a private unreferenced orphan is preferable to a broken committed reference.
5. POST /api/v1/accounts/{account_id}/cookie-login accepts strictly bounded streamed JSON with exactly cookie, platform, expected_auth_revision, frontend_generation, enable_mediacrawler and accept_mediacrawler_license. Authentication/CSRF/license gates remain mandatory; parse errors only expose fixed codes, never input, field names or exception details. Reply with the existing 202 Operation start contract. Request identity stores only a digest and fixed identity fields; no raw candidate. Share account-login exclusion plus the actual account lock across candidate validation/publication. Success summary is exactly account_id/auth_status=authenticated/login_method=cookie/auth_revision. Existing Operation reads provide progress/outcome.
6. Expose auth_revision and pasted_cookie_login capability. Accounts gets an explicit paste/verify/save dialog with memory-only input, no preview or logging, fixed error guidance and no automatic retry. Clear on submission/close/logout/account switch; fence late responses by account/platform/session/generation/operation. A failure states the previous credential is unchanged; closing after submission does not falsely claim server cancellation. Allow replacement of an authenticated account with a current revision. Keep the existing QR option and accurately label unsupported platforms.
7. Fix deterministic downstream reuse: Cookie forward/detail requests must use an empty non-persistent context and the full parsed supplied header, never let an old saved-session profile bypass candidate injection. Test equals-containing values and stale browser-session traps. Bili Cookie profile lookup is a required follow-up dependency of this workflow; do not pretend saved-session-only profile support automatically covers Cookie accounts.
8. Parallel ownership: runner/parser/upstream contracts and Cookie reuse; managed storage/Account CAS/migration; Web/controller; root Operation/API/service and integration. Validate parser/leak sentinels, fake network response rejection, process timeout/cancel/tree cleanup, failed-candidate preservation, atomic success/ABA/cancel/lease, fresh-process credential resolution, migration/package and UI session races. Record actual failures and all skipped/live gates in bilingual docs; bilingual commits and non-force push followed by fresh fetch. No production login/Cookie input/deployment/subscription mutation/capture/download/export or supervisor restart is authorized here.

The first four-platform delivery does not complete 0058 or the seven-platform goal. Remaining authenticated proof for three platforms, Bili Cookie profile dependency, bounded history coverage and live end-to-end qualification stay explicit obligations.
