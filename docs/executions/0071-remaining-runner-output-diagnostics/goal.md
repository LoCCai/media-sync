# Goal: safe diagnostics for remaining runner output

Extend execution 0070's safe segmented process-output diagnostics to the independently isolated paths that it explicitly deferred: pasted-Cookie validation, creator-profile lookup, content-detail/media-address resolution, and only the download/probe/remux/avatar helper boundaries that a fresh process inventory shows can safely contribute evidence. Keep all retained evidence in the existing managed JSONL segments so failures can be correlated without creating a raw-output archive.

This remains selective diagnostic capture, never a transcript. Raw Cookie or Authorization values, QR payloads or images, signed URLs, upstream JSON/JSONL, HTML/DOM, request or response bodies, creator metadata, media bytes, and private filesystem paths must never be persisted. Protocol stdout, framed results, ffprobe output and avatar PNG bytes remain business channels rather than logs. In-process HTTP, DNS and file streaming have no child output to capture; they may emit only closed lifecycle events with no body or media content.

This execution starts from repository baseline `571f993`. It does not deploy the edited tree, restart the supervisor, retry a real platform operation, read production credentials, or claim that QR scanning has been fixed. Older output that was discarded cannot be recovered, and new diagnostic evidence exists only after this version is deployed and a separately authorized operation runs.

## Acceptance criteria

1. Reuse execution 0070's `state_dir/logs` store, closed `process_output` event family, redaction policy, 4 MiB/4,096-line/64 KiB-line limits, rotation, retention, capacity and managed-path protections. Do not create another log sink or loosen the classifier to capture “all” third-party text.
2. Freeze an explicit trust and process inventory before wiring anything. Length-framed Cookie/profile guardian and worker stdout, detail result stdout, ffprobe stdout and avatar PNG stdout remain exclusively protocol or binary data. The Cookie/profile guardian stderr is currently an unread pipe and must not become a diagnostic transport or an additional writer that can block.
3. Generalize capture only as needed for current-process fd capture and safe single-diagnostic-stream draining. Restore descriptors and finish capture before emitting a result frame or PNG. Capture startup, drain, filtering, summary or sink failure must not change a runner's return value, authority decision, retry classification, deadline, cancellation or process-tree cleanup.
4. Capture safely classifiable diagnostics only around the Cookie worker's remote verification and the creator-profile worker's platform lookup. The known Cookie and secret creator references may be supplied only in memory to redaction. Neither the guardian protocols nor profile result objects may be persisted as log text.
5. Capture detail diagnostics only around the child execution that resolves the exact content and media locators, then restore protocol stdout before emitting the bounded result frame. Raw detail rows, creator/content fields and signed media addresses never enter events or summaries.
6. For the download path, emit only closed lifecycle evidence for in-process HTTP/DNS/file work after an exact asset-download identity exists. Capture only policy-approved stderr from the inventoried ffprobe/ffmpeg probe, mux, remux and concat processes while keeping stdout for its parser. In the avatar worker, capture only retrieval/decoding diagnostics and restore stdout before writing PNG bytes.
7. Bind events only to validated canonical local identities: Cookie/profile operations and accounts, detail account/subscription/platform plus available asset context, and download Job/asset identities created by the authoritative application boundary. Extend the cross-process envelope only with a closed set of canonical UUIDs; reject the whole propagated value on an extra, malformed, mixed or noncanonical field. Direct or untrusted runner invocation remains quiet.
8. Authenticated log APIs and the Chinese log-center UI continue to show only validated safe messages, summaries and fixed dropped reasons. Deterministic adversarial and real-subprocess tests prove byte-exact protocol isolation, no guardian deadlock, exact correlation, secret/content/media absence from both validated events and raw managed segment bytes, and unchanged business outcomes when logging is unavailable. Record focused and repository-wide gates exactly; Linux, live-platform and QR qualification remain `NOT_RUN` unless actually executed.

## Deferred but unchanged

- Deploy the completed version and run separately authorized controlled operations before using the added evidence to select any platform fix. This observability work does not repair QR scanning, Cookie acceptance, platform behavior, downloading or playback by itself.
- Preserve checkout/prefetch/readiness helpers that have no exact durable work identity or already discard output unless a later inventory and threat review establishes a safe need. Do not broaden capture merely because a subprocess exists.
- Continue the seven-platform subscription, historical backfill, risk-controlled download, incremental synchronization and Emby/Jellyfin-compatible directory objective. This diagnostics slice supplies evidence and must not replace or narrow that product work.
