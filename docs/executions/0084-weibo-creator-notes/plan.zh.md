## 2. 耐久游标与停止原因

- 迁移 `0018_weibo_creator_notes` 创建 `weibo_subscription_progress`，约束纪律与 0015–0017 相同：封闭 `phase` 白名单、四个固定停止原因、计数范围、全有或全无证据三元组、`blocked_code` 当且仅当 `blocked`、受护栏下线。
- `wb-work-v1:` 不透明游标携带：`since_id`、页见证、单元索引、已完成笔记 ID、头部边界、停滞单元计数、已消耗页数与上一单元摘要。不携带其他内容，绝不携带媒体 URL 或 `mblog` 载荷。

## 3. 有栅栏的有界续跑

- 每步至多一个按页界定的单元；上限就是 `max_items` 本身，因为上游页大小是算术常量而非请求参数。
- 被截断的页绝不推进游标：重发同一 `since_id`，并按 `mblog.id` 跳过已交付笔记。
- 续跑延迟经 `MEDIA_SYNC_WEIBO_SCAN_CONTINUATION_DELAY_SECONDS`（默认 300，两个服务必须一致）。

## 4. 对账与增量头部检查

- 保留的推断结束后，从空游标做一次有界头部重列，必须复现记录的边界，才进入增量轮询。
- 增量模式重列有界头部页，只为未见或变化的笔记抓详情。

## 5. 按 Content 交付

- 只有完整媒体形状在场的笔记才发布；失败笔记按固定码计数，绝不阻塞无关笔记。
- 重启与零工作重放保留内容寻址字节与确定性 NFO 输出。
