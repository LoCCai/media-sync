## Outcome / 目标结果

Execution 0019 will extend the automatic creator-subscription media pipeline to a sixth platform by qualifying one narrow Zhihu shape: an ordinary creator answer whose body contains exactly one eligible static `zhimg.com` image and no nested playable-video or animation marker. The locked MediaCrawler answer path will remain unmodified; an integration-owned runtime shim will retain the image locator that upstream currently discards before JSONL. A bounded creator lookup will discover the answer, and an exact canonical answer-detail lookup will reacquire the current image locator in memory before download. / Execution 0019 将把自动作者订阅媒体闭环扩展到第六个平台，只验收一个狭窄的知乎形状：作者普通回答正文中精确包含一张合格的 `zhimg.com` 静态图片，且不含嵌套可播放视频或动图标记。锁定的 MediaCrawler 回答链保持不修改；由集成拥有的运行时 shim 会保留上游目前在 JSONL 前丢弃的图片 locator。有界作者查找负责发现回答，精确 canonical 回答详情查找会在下载前于内存中重新取得当前图片 locator。

The offline composition will bind exact SQLite Account/Subscription/Author/Content/Asset provenance, mock public DNS/HTTP, a real decodable static-image fixture, production image validation, immutable SHA-256 archive identity and the existing Emby/Jellyfin poster/gallery/NFO/source layout. Query-only replay must perform no second detail, DNS, HTTP, probe, archive or export operation. / 离线组合将绑定精确 SQLite Account/Subscription/Author/Content/Asset 来源，并贯穿 mock 公网 DNS/HTTP、真实可解码静态图片夹具、生产图片校验、不可变 SHA-256 归档身份及现有 Emby/Jellyfin poster/gallery/NFO/source 布局。仅 query 变化的重放不得再次执行 detail、DNS、HTTP、probe、归档或导出。

## Why this slice / 选择依据

- The locked creator flow calls only `get_all_anwser_by_creator`; article and video creator calls are commented out. Its answer API explicitly requests raw `content` HTML, so ordinary answer images already reach an integration-owned interception point without enabling a new upstream content family. / 锁定的 creator 流只调用 `get_all_anwser_by_creator`；文章与视频 creator 调用均被注释。回答 API 明确请求原始 `content` HTML，因此普通回答图片已到达可由集成拦截的位置，无需启用新的上游内容族。
- Locked `ZhihuExtractor._extract_answer_content` converts `answer.content` through `extract_text_from_html`, which removes every HTML tag and image attribute. `ZhihuContent` has no media field, after which `model_dump()` and the JSONL store can preserve only text and landing-page metadata. The loss boundary is therefore exact and shim-compatible. / 锁定的 `ZhihuExtractor._extract_answer_content` 通过 `extract_text_from_html` 转换 `answer.content`，会删除全部 HTML 标签与图片属性。`ZhihuContent` 没有媒体字段，随后 `model_dump()` 与 JSONL store 只能保留文本及落地页元数据。因此丢失边界精确且适合 shim。
- The current creator-answer pagination runs until upstream `paging.is_end` and does not honor `CRAWLER_MAX_NOTES_COUNT`. This execution includes an integration-owned successful bound rather than relying on an output watchdog to fail after excessive work. / 当前作者回答分页会一直运行到上游 `paging.is_end`，且不遵守 `CRAWLER_MAX_NOTES_COUNT`。本执行会增加由集成拥有的成功边界，而不是依赖输出 watchdog 在过量工作后失败。
- Article thumbnails/inline images require explicitly enabling and bounding a creator path that upstream currently disables. Dedicated zvideo playback and cover fields are nested inside an unfrozen raw structure. Neither belongs in this minimum source-bound slice. / 文章缩略图/内嵌图片需要显式启用并约束上游当前关闭的 creator 路径；独立 zvideo 播放与封面字段则嵌套在尚未冻结的原始结构中。两者均不属于本次最小源码绑定切片。

## Acceptance boundary / 验收边界

1. Creator sync uses the exact trusted Zhihu Subscription creator reference and returns successfully after at most the configured `max_items`; page size, offset progression, malformed data, repeated/no-progress paging and output limits are bounded and fail closed. Truncation at `max_items` must not fetch or write another page. / creator 同步使用精确可信的知乎 Subscription 作者引用，并在最多处理配置的 `max_items` 后成功返回；页大小、offset 推进、畸形数据、重复/无推进分页及输出限制均受约束并关闭失败。达到 `max_items` 的截断不得再抓取或写入下一页。
2. The qualifying row is exactly `content_type="answer"`, has canonical positive answer/question identifiers and contains ordinary bounded HTML with exactly one eligible image. Zero images retain the historical text-only ARTICLE behavior but are outside this media claim; two or more images, duplicate image nodes/locators, malformed-plus-valid candidates, nested video/iframe/player markers, GIF/SVG/animation and container drift produce no qualified Asset and fail detail refresh closed. / 合格行必须精确为 `content_type="answer"`，具有规范正整数回答/问题 ID，并包含普通有界 HTML 与精确一张合格图片。零图片继续保持历史纯文本 ARTICLE 行为，但不属于本次媒体声明；两张或更多图片、重复图片节点/locator、畸形+有效候选、嵌套 video/iframe/player 标记、GIF/SVG/动图及容器漂移均不产生合格 Asset，并在详情刷新时关闭失败。
3. Image selection follows one frozen attribute contract, preferring `data-original`, then `data-actualsrc`, then `src`; duplicate selected attributes, surrounding whitespace, control characters and ambiguous alternate candidates fail closed. The initial locator must be bounded HTTPS on a strict LDH `zhimg.com` subdomain, use a non-root static `.jpg`, `.jpeg`, `.png` or `.webp` path, have no userinfo, fragment, backslash or custom port, and may retain a transient query. Redirect destinations remain governed by the existing per-hop public-network checks. / 图片选择遵循一个冻结属性契约，依次优先 `data-original`、`data-actualsrc`、`src`；重复的选中属性、首尾空白、控制字符及歧义的其他候选均关闭失败。初始 locator 必须是有界 HTTPS、位于严格 LDH `zhimg.com` 子域、使用非根静态 `.jpg`、`.jpeg`、`.png` 或 `.webp` 路径，不得含 userinfo、fragment、反斜杠或自定义端口，并可保留瞬态 query。重定向目标继续受既有逐跳公网检查约束。
4. The shim is installed only after verified-checkout import and before upstream execution. It wraps the locked answer extractor, attaches a runtime-only frozen capture to the exact returned `ZhihuContent`, binds that object through a task-local context while `update_zhihu_content` runs, and enriches only the matching JSONL row under one versioned media-sync private field. Wrong checkout, partial/double installation drift, field collision, content identity mismatch and cross-task leakage fail closed. `.upstream` remains unmodified and untracked. / shim 只能在校验过的 checkout 导入后、上游执行前安装。它包装锁定回答 extractor，把仅运行时存在的冻结捕获绑定到精确返回的 `ZhihuContent`，在 `update_zhihu_content` 运行期间通过任务局部上下文绑定该对象，并只在一个版本化 media-sync 私有字段下增强匹配 JSONL 行。错误 checkout、部分/重复安装漂移、字段冲突、内容身份不匹配及跨任务泄漏均关闭失败；`.upstream` 保持未修改且不纳入跟踪。
5. The normalized content remains `ContentKind.ARTICLE`; it has exactly one position-zero `AssetKind.IMAGE` with remote identity `<content_id>:image:0`. Discovery persists only a query/userinfo/fragment-free source hint and strips the shim field from durable raw. Refresh accepts only the exact canonical `https://www.zhihu.com/question/<question_id>/answer/<content_id>` reference retained with the content, requires one matching answer and one matching IMAGE identity/source hint, and returns the current URL with `MediaRequestProfile.DEFAULT`. Cookies or account authority must never be forwarded to the image CDN. / 归一化内容继续使用 `ContentKind.ARTICLE`，并精确拥有一个 position 0 的 `AssetKind.IMAGE`，remote identity 为 `<content_id>:image:0`。发现阶段只持久化无 query/userinfo/fragment 的 source hint，并从持久 raw 中移除 shim 字段。刷新只接受随内容保留的精确 canonical `https://www.zhihu.com/question/<question_id>/answer/<content_id>` 引用，要求唯一匹配回答及唯一匹配 IMAGE identity/source hint，并使用 `MediaRequestProfile.DEFAULT` 返回当前 URL。Cookie 或账户权限不得转发给图片 CDN。
6. One offline SQLite-to-Emby composition proves exact provenance, bounded detail execution, mock public DNS/HTTP, production decoding of a real static image, immutable archive checksum/path, deterministic poster/gallery/NFO/source publication and zero-work replay. Completed attempt roots and transient query values are absent from retained durable artifacts. / 一个 SQLite 到 Emby 的离线组合会证明精确来源、有界 detail 执行、mock 公网 DNS/HTTP、生产代码解码真实静态图片、不可变归档校验和/路径、确定性 poster/gallery/NFO/source 发布及零工作重放。已完成 attempt 根与瞬态 query 值不得出现在保留的持久产物中。
