# 下一阶段：订阅到文件

这是确认的后续顺序，不是已完成实现。头像扩展的优先级低于可用的采集下载闭环。

1. **目录设置：** 可编辑媒体总目录、默认平台子目录、逐平台独立目录。数据库保存策略及修订，API 和 supervisor 共享，在有所有权保护的任务边界解析并冻结。预览容器内最终路径，明确两个服务采用相同挂载；禁止私有目录交叠与符号链接逃逸。保留旧输出根与记录，保存不隐式搬移、删除或批量重写。已有媒体需不可变位置绑定，或阻止激活改根直到完成明确迁移。
2. **一个订阅的一次完整执行：** 明确操作仅针对选中订阅，依次执行发现、下载、校验与兼容目录写入，不处理其他订阅。展示发现、下载、落盘、失败数量，不把 Worker 成功当作媒体采集成功。
3. **历史转增量：** 为每个内容源持久化历史完成、分页续跑及新内容水位。B 站目前有界交替扫描头部、历史和内容源，但没有永久历史完成标志；其他平台需逐一核验覆盖。保证中断续跑与去重，批次完成不等于历史完成。
4. **部分成果可见：** 当前作者流水线需所有符合条件的资产验证通过后才写入目录。设计按完整内容单位安全写入，避免一项旧资产不可用就长期挡住其他已验证的新作品，同时保留多分 P、图集等完整性约束。
5. **风控处理：** 保留请求上限和限速，将有明确证据的认证、验证与限流响应接入暂停/退避及易懂诊断。调度器已有状态名不代表各平台真实输出已接通，不自动绕过验证，不轮换凭据或代理。
6. **真实验收：** 用已授权账户和明确确认的一个作者做限量验收，协调 supervisor 和下载范围；检查实际内容、媒体字节、最终目录及无重复重跑，再验收历史续跑和定时增量。在新证据证明替代成功前，保留既有 B 站失败记录。

必验：设置跨重启及并发编辑、在途任务保持输出修订、不泄露凭据、单项失败不破坏已验证输出、精确订阅范围、无需服务器 API、零工作重放；未测线上环节明确标记未运行。
