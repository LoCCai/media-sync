## Delivered / 已交付

- Added additive migration `0003_media_download_emby` and upgrade/downgrade/re-upgrade coverage. Complete legacy `verified` rows retain their lifecycle and receive normalized checksum/timestamps; legacy `downloading`, `downloaded`, `exported` and incomplete `verified` rows reset to `discovered`, clear downloader-owned fields and record `legacy_asset_reset`. Downgrade clears every `assets.download_job_id` and deletes all generation-bound `asset_download` Jobs. It deletes non-succeeded Emby identity poison, but preserves succeeded publication-chain Jobs/records plus a non-succeeded Job and its named records when a structurally valid closed publication intent must remain available for exact post-publish recovery. Asset discovery and downloading now have explicit field ownership; semantic and locator fingerprints plus a fenced generation reset prevent discovery replay from downgrading or mismatching verified bytes.
- Closed locator schema v1 around canonical `direct` and `adapter_refresh` forms. Persisted direct URLs reject credentials, query, fragment and non-HTTP(S) schemes; refresh may return an ephemeral signed URL in memory, while an unavailable refresh capability returns fixed `locator_refresh_unsupported`.
- Extended sink redaction for composite API/access-key mapping names across snake_case, kebab-case, camelCase and provider-prefixed forms, while deliberately preserving ordinary `key`, `public_key` and `key_id` fields. Credential-marker URL paths and assignments are detected through bounded decoding in raw, encoded and double-encoded forms; generic URL output redacts the path, `direct` parsing rejects it, and asset source-hint derivation returns no hint so persistence uses stable `adapter_refresh`. The `0003` legacy backfill mirrors that rule, clears an unsafe `source_url`, and never copies the credential path into SQLite locator state.
- Added a same-`work_root` per-asset OS orchestration lock held from before `_begin` through database finalization. Lock contention returns `asset_download_busy` with zero job/asset/attempt mutation. Each durable job stores only a non-reversible hash of canonical work/archive roots; a different scope is rejected before reclaim or attempt mutation. Exact owner/token renewal after nominal expiry is allowed only if reclaim has not won, so renewal versus reclaim is a single-winner CAS.
- Added strict asset and durable-job lifecycle CAS, fresh lease fencing tokens, exact job claiming, retry limits and atomic asset/job finalization. DNS/network/filesystem work is kept outside SQLite transactions.
- Implemented per-hop public-address validation, mixed public/private DNS rejection, address-pinned Host/SNI-preserving connections, manual redirects, environment-proxy disablement, redirect bounds, HTTPS downgrade rejection, and cross-origin validator stripping.
- Implemented generation-bound `.part` resume metadata and strict `200`/`206`/`416`, `Range`, `If-Range`, validator, total-length, timeout, header and byte-limit handling, including bounded restart behavior.
- Added magic/MIME validation and mandatory bounded `ffprobe` structural probing for audio/video, then SHA-256 publication to immutable `archive/sha256/<prefix>/<digest>.<verified-extension>` blobs. The ownership guard runs after temporary copy/fsync/rehash and immediately before no-clobber commit, including existing-blob reuse. Existing blobs are revalidated; path escape, links/reparse/hardlinks present at operation time and detected leaf-identity replacement fail closed. Configured roots and ancestors are explicitly trusted operator-controlled directories; malicious same-permission parent-directory substitution is outside the 0.x threat model.
- Added the download application service with short claim/start and atomic verify/complete transactions, redaction-safe fixed errors, lease/generation fencing and resumable retry. `.part` evidence is retained until database success; a committed archive whose final database transaction failed can be recovered without network or a new attempt, including an expired last attempt. Cleanup is best-effort after verification and cannot reverse success. Verified shortcuts revalidate the canonical blob; corrupt bytes are quarantined and missing/invalid persisted archive state is CAS-reset instead of trusted.
- Implemented deterministic Emby/Jellyfin layout v1 with title-independent creator/content identities, UTC-year seasons, stable episode numbers, valid UTF-8 NFO XML, allowlisted provenance, playable verified video/audio, deterministic artwork selection, and preservation of gallery/text/attachment assets.
- Added author-scoped process/OS locking, job-ID staging, managed-file hashes, journal-before-mutation no-clobber publication, rollback/recovery and complete desired-tree byte verification before success. Interrupted roll-forward validates every manifest-listed file before discarding its journal; mismatch retains `RECOVERY_REQUIRED`. User-modified and unmanaged files are preserved; ambiguous rollback leaves retained evidence instead of recursively deleting user paths.
- Added a durable database publication protocol. Every succeeded `export.emby` Job result anchors publication scope, source/tree/manifest hashes, managed-file count and its exact predecessor Job. The unique predecessor chain—not timestamps or a manifest discovered only from disk—determines the current head. Natural identity includes the source and exact predecessor, allowing `A → B → A` while rejecting graph forks, cycles and broken ancestry.
- Added pre-publish Job `intent` persistence and publish-success/database-finalize recovery. A later call may atomically complete the exact records and Job only after the intended source/tree/manifest and every managed byte validate. First export rejects an unexpected managed manifest; a self-consistent forged manifest cannot claim an unmanaged user file. Empty snapshots remain anchored without ExportRecords, and concurrent sibling publications leave one durable winner while the stale loser retries from the new head.
- Added strict `ExportRecord` begin/complete/fail CAS and an export application service. Export completion belongs to exporter/version/whole-author-snapshot fingerprints rather than globally advancing an asset to `exported`.
- Added redaction-safe `media-sync asset list`, `media-sync asset download`, and `media-sync emby export` commands. `asset list` omits locators, URLs, archive paths and raw metadata. Missing mandatory `ffprobe` and unsupported MediaCrawler refresh preflights return `blocked`/`not_started`, the unchanged `persisted_status` and fixed codes without creating a Job or changing the Asset.
