# 进展：六方向独立代码审查

状态：本地已实现并验证。未部署，未使用真人账户或平台请求。

## 结果

审查发现 0085 与 0086 按已交付状态**并不可用**。两者都有绿色本地套件，也都会在第一次真实运行时失败：

- 贴吧与知乎从未完成过一个有界单元——捕获 shim 在封印覆盖见证之前就中止（按位置回放的循环、调用上游 store 回调），而 `NormalizedMediaCrawlerOutput` 静默丢弃了两份覆盖载荷，使 handler 把每次运行都判为 `output_security_failed`。
- 即便过了这一关，也没有任何进度行能推进：管线 worker 从不发布知乎进度，且没有任何微博/贴吧/知乎回执携带 `source_run_id`，于是每个 publisher 都在 schema-1 回执上返回 `None`。
- WebUI 根本到不了耐久链：九个服务构造点全部漏掉了新的续跑策略，策略因此取默认值，进度行从不物化。

这正是自写测试套件抓不到的那类缺陷，也是本次审查被发起的原因。

## 已修

六个方向共 26 个缺陷，每条都在改动前重新核实，并由回归测试钉住：

- **功能性、阻断级（4）：** 知乎按位置回放；贴吧/知乎上游回调二次写入；覆盖载荷未透传；知乎 publisher 缺失。
- **功能性、耐久链（6）：** 缺 `source_run_id`；微博把停滞页计为已消费页；贴吧越过停滞页；贴吧空页当源末；知乎部分重叠阻塞；知乎空响应体硬报错。
- **摄取边界（2）：** B 站 30 条上限被套用到所有平台；微博 `declared_total` 超出列边界。
- **安全（4）：** `secure_delete` 未覆盖 WAL 旁文件；注入的 Alembic 连接不带 pragma；`db status` 使用未托管引擎；ffprobe/ffmpeg 继承整个环境。
- **前端（6）：** 二维码中继不可达；快手停止原因不匹配；缺微博/贴吧/知乎面板；修订白名单陈旧；概览单点失败拖垮全部；错误文案缺失与剪贴板静默失败。
- **操作者契约（4）：** 每个构造点都缺续跑策略；两个修订 ID 实为文件名；两个守卫元组只覆盖四个平台；`models.__all__`。

## 已驳回

两条审查结论未能通过重新核实，已如实记录，使报告不夸大发现。

## 已报告但刻意未修

四条发现真实存在，但属于已冻结的更早执行（0076/0081/0083）：抖音 8 项 `bit_rate` 上限静默禁用 0083 的排序、快手缺 CDN 允许列表、小红书接受明文 `http`、动画图片在五个平台上被当作静态图。各自需要独立执行并重新推导钉定上游事实；在此改动会静默改变已交付行为。
