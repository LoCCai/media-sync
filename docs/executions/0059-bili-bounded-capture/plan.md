# Frozen implementation plan

1. Use the locked MediaCrawler client/store and existing browser/auth/Cookie/account-lock supervision. Add an owned in-memory Bili creator shim, not modifications or vendored copies of restricted upstream source. Replace the unbounded ordinary-upload loop, explicitly send order=pubdate, and do not call its error-swallowing get_specified_videos helper. This path requests no dynamics, fans, follows, comments, play URLs or media bytes. Those feeds/shapes remain separate required work.
2. Establish a closed, versioned upload-scan state bound to account, author, locked SHA, feed, order and fixed page size30. Persist it within the existing opaque {value:string} subscription cursor, not an incompatible raw page object. Retain bounded pending identities and an exact page witness. A unit consumes at most min(max_items,30) verified details, with at most two author-list HTTP attempts; failed attempts count and no automatic client retry may exceed these budgets. Existing time/output/process limits and configured request delay remain active. Authentication/browser setup is a separately disclosed bounded-runtime cost, not falsely counted as one author page.
3. Alternate a head-update lane and a historical lane so continuing new uploads cannot permanently starve backfill. Each lane retains its own page/pending/witness. Head scans all items at or above its previous fully consumed timestamp (including every same-second item), and only adopts its candidate upper boundary after reaching strictly older data or observed source end. Initial head authority is not derived from a legacy database watermark. Historical scans never apply the forward timestamp filter; after observed exhaustion, later sweeps allow rechecking late/backdated content. Replaying existing records is idempotent, not an assertion that no HTTP work occurred.
4. Preserve every selected but unconsumed identity across successful units; detail failure, wrong author/aid/bvid/pubdate, malformed response, cancellation or lease loss cannot consume it. Before advancing beyond a consumed page, re-read its fixed-size identity witness; if it changed, restart that lane conservatively without promoting coverage. The remote pn API has no snapshot guarantee: guarantee no silent loss of discovered queued identities and no false completeness, not absolute recovery of content that disappears before it can be fetched. Source-end observation and head-boundary observation are scoped evidence, never global historical completeness.
5. Extend the existing manifest with an optional explicitly versioned Bili-scan sub-contract while preserving byte-for-byte serialization of old manifests. New Bili executions carry scan state; old artifacts gain no bounded or exhaustive semantics. Write exactly one reserved owned JSONL coverage sidecar in the output tree, containing the bound input/next state, consumed identities, counters and fixed stop reason. The ordinary receipt seals its exact bytes along with content output after process-tree cleanup. Parent normalization cross-checks manifest identity, sidecar shape, selected/details/content agreement and budgets; missing/forged/extra/mismatched coverage grants no checkpoint advancement.
6. Add a Bili bounded ingestion path reusing existing batch/source provenance and lease/CAS infrastructure. Its at-most30 records, source observations, next cursor, run counts and succeeded state publish in one short transaction. Do not promote or filter by the old highest-item watermark. Recovery is idempotent and must not overwrite a newer cursor; an ambiguous post-commit acknowledgement is resolved from durable exact-Run truth. Keep Run succeeded as a trustworthy completed unit so current exactly-once pipeline enqueue remains valid. A partial unit may publish verified content; max_items is not a download-scope limit because the pipeline currently selects the subscription's pending assets.
7. Wire actual scheduler and relevant CLI paths, account/Cookie variants, and safe API/UI coverage projections. Bili no longer requires an unbounded-history acknowledgement when the new bounded sub-contract is active; legacy unbounded artifacts remain gated. Show per-unit limit, head/history activity, partial/restarted/source-end observation and next action without exposing raw cursors, pending IDs, signed URLs, credentials or host paths. No hidden background live run or automatic deployment.
8. Validate actual locked signed query order; fixed-page/request/detail budgets; more-than30 content with max_items1 across restarts; same-second and new uploads during backfill; page insert/delete/reorder drift; wrong/absent detail; sealed coverage tamper; cancel/lease/CAS/partial recovery/ambiguous commit; source provenance; exact pipeline enqueue; and unchanged account/auth/other-platform behavior. Use independent review, focused tests, complete available offline directories, Web/static/build/package/upstream/docs gates, bilingual Git commits and non-force push with fresh-fetch equality. Keep all initial failures, corrected runs and environment/live skips in the journal.

No production login, Cookie input, subscription mutation, sync retry, download/export, media-server action, deployment or supervisor restart occurs in this coding execution. Live deployment/canary authorization must be obtained separately. Implementation details may be refined before their dependent edits, but may not replace persistent complete coverage semantics with latest-N truncation.
