# 冻结实施计划

1. 复用锁定MediaCrawler客户端/store及现有浏览器/认证/Cookie/账户锁监督，新增本项目拥有的进程内B站creator钩子，不修改或复制受限上游源码。替换无限普通投稿循环，明确发送order=pubdate，不调用会吞详情错误的get_specified_videos。此路径不请求动态、粉丝、关注、评论、播放URL或媒体字节；这些feed/形状作为独立必做工作保留。
2. 建立封闭版本化投稿扫描状态，绑定账户、作者、锁定SHA、feed、排序和固定页大小30，写入现有不透明{value:string}订阅cursor，而非不兼容的裸page对象。保留有界待消费身份与精确页见证。每单元最多消费min(max_items,30)个已验证详情，最多两次作者列表HTTP尝试，失败尝试也计数、客户端不能自动重试超预算。保留时间/输出/进程限制和配置的请求间隔；认证/浏览器初始化是单独披露的有界运行成本，不假称只有一个作者页请求。
3. 交替推进头部更新与历史通道，持续新投稿不能永久饿死回填；每通道独立保留page/pending/witness。头部扫描上次完整消费时间及其以上所有条目（含同秒全部项），遇严格更旧条目或观察到源末尾后，才采纳候选上界。初始头部权威不从旧数据库水位推断。历史不使用前向时间过滤；观察到末尾后，后续周期重新核查迟到/回溯时间内容。重复数据幂等，不声称没有HTTP工作。
4. 成功单元之间保留每个已选未消费身份；详情失败、作者/aid/bvid/pubdate错配、畸形响应、取消、丢租约均不能消费。跨越已消费页前重读固定大小身份见证；发生变化则保守重启该通道，不提升覆盖结论。远端pn接口没有快照保证：保证已发现待消费身份不静默丢失、不虚假完整，不承诺抓到获取前已消失的内容。源末尾/头部边界观察仅为指定范围证据，不是全历史完整。
5. 现有manifest增加可选且明确版本化的B站scan子契约，旧manifest序列化逐字节保持原样。新B站执行携带状态，旧artifact不获得有界/穷尽语义。输出树写一个专用保留名称的JSONL覆盖sidecar，含绑定的输入/下一状态、消费身份、计数、固定停止原因；普通receipt在完整进程树清理后连同内容封存精确字节。父进程规范化交叉校验manifest身份、sidecar形状、所选/详情/内容一致及预算；缺失/伪造/多余/错配覆盖不推进checkpoint。
6. 新增B站有界入库路径，复用已有批次/来源和lease/CAS基础设施；最多30条记录、来源观察、下一cursor、run计数及succeeded在一个短事务发布，不抬高或应用旧最大时间水位。恢复幂等且不能覆盖更新cursor；提交确认不明确从精确Run持久真值判断。保留Run succeeded表示可信完成单元，兼容现有exactly-once pipeline入队。partial单元可发布已验证内容；max_items不是下载范围限制，因为现有pipeline选择订阅待办资产。
7. 接通实际scheduler和相关CLI、账户/Cookie变体及安全API/UI覆盖投影。启用新子契约时B站不再要求无限历史确认，旧无限artifact继续门控。展示每轮上限、头部/历史活动、partial/重启/源末尾观察与下一步，不暴露原始cursor、待办ID、签名URL、凭据或宿主路径。没有隐含后台真人运行或自动部署。
8. 验证实际锁定签名排序、固定页/请求/详情预算、max_items1跨重启取得超过30条、同秒及回填期间新投稿、插入/删除/重排漂移、错配/缺失详情、覆盖封存篡改、取消/租约/CAS/恢复/提交确认不明、来源绑定、精确pipeline入队及认证/其他平台不回归。独立审计、专项、可用完整离线目录、Web/静态/构建/打包/上游/docs门，双语Git提交并非force推送/fresh-fetch相等；保留初始失败、修正复跑及环境/真人跳过证据。

此编码执行不操作生产登录、Cookie输入、订阅、同步重试、下载/导出、媒体服务器、部署或supervisor；部署/金丝雀需另获授权。细节可在依赖修改前细化，但不得用latest-N截断代替持久化完整覆盖语义。
