# 安全部署、配置与运维计划

## 1. 当前必须立即处理的暴露风险

现场 compose 使用：

```yaml
ports:
  - "0.0.0.0:8632:8632"
```

而应用明确没有自身鉴权。该端口一旦被公网路由、防火墙或面板转发，就能被访问者执行：

- 添加账户；
- 启动登录；
- 添加订阅；
- 启动爬取；
- 下载/校验；
- 导出；
- 查看部分运行状态。

在 Web v2 增加更多恢复和管理功能后，风险会进一步扩大。

## 2. 立即部署基线

### 方案 A：仅宿主机反向代理

```yaml
ports:
  - "127.0.0.1:8632:8632"
```

由宝塔/Nginx 反代，并至少启用：

- 强密码 Basic Auth 或统一认证；
- HTTPS；
- WebSocket/SSE 代理设置；
- 访问日志；
- IP 白名单。

### 方案 B：仅局域网

绑定精确 LAN 地址，而不是所有地址：

```yaml
ports:
  - "192.168.31.249:8632:8632"
```

同时用主机防火墙限制到可信网段。

### 方案 C：Tailscale/WireGuard

只发布到私有隧道地址，是最适合个人自托管的远程访问方式。

## 3. 健康检查

容器内 healthcheck 使用：

```text
http://127.0.0.1:8632/api/v1/health
```

不应使用 `0.0.0.0` 作为客户端目标。

分层：

- liveness：进程；
- readiness：数据库；
- deep readiness：checkout、浏览器、ffmpeg、路径；
- qualification：真人平台与 Emby。

## 4. 单操作者鉴权

Web v2 首期无需多用户，但必须支持单操作者保护。

推荐两种模式：

### External auth

信任反向代理注入的已验证身份头，但必须：

- 配置 trusted proxy；
- 直连端口不可达；
- 清理客户端伪造头；
- 显示当前认证模式。

### Built-in operator session

- 首次启动设置密码；
- Argon2id 哈希；
- HttpOnly、Secure、SameSite cookie；
- CSRF；
- 会话过期；
- 登录限速；
- 审计登录；
- 不支持通过 URL token 登录。

## 5. 配置中心

配置分级：

### 可在线修改

- 默认 interval；
- max_items；
- request delay；
- 日志保留；
- Emby 扫描行为；
- 页面偏好。

### 修改后重启

- API bind；
- state/archive/export/job root；
- MediaCrawler Python；
- browser path；
- proxy；
- SQLite URL。

### 只读构建事实

- app SHA；
- upstream SHA；
- base digest；
- uv/node/playwright/chromium/ffmpeg；
- lock digests。

## 6. Proxy 设计

区分：

- 构建代理；
- MediaCrawler API代理；
- 媒体 CDN代理；
- Emby 内网连接；
- no_proxy。

不要把代理凭据写入：

- Docker image layer；
- build manifest；
-普通 settings API；
-日志。

使用 BuildKit secret 或运行时 secret ref。

## 7. 备份恢复中心

Web 可驱动但必须保持安全：

- 在线 SQLite backup API；
- archive 增量备份计划；
- 导出媒体库可再生成标识；
- profile 备份可选且含登录敏感数据；
- 恢复前 dry-run；
- 恢复需要二次确认和维护模式；
- 操作进程不能覆盖正在运行的数据库。

首版只展示命令和状态；自动恢复放在后续执行。

## 8. 升级

升级前检查：

- 工作区和版本；
- 数据库 revision；
- 可用空间；
- backup；
- upstream lock；
- migration；
- image digest；
- breaking changes；
- rollback 限制。

升级后：

- health；
- ready；
- deep readiness；
- schema；
- supervisor；
- 一次 Fake smoke；
- 不自动触发真人抓取。

## 9. 文件权限

- `/data` 由固定 UID/GID 管理；
- bind mount 前检查权限；
- profile 目录 0700；
- secret 文件 0600；
- archive blob 不可覆盖；
- library 可由 Emby 只读挂载；
- Web 不提供任意文件浏览器。

## 10. 安全响应头

同源 Web：

- Content-Security-Policy；
- X-Content-Type-Options；
- Referrer-Policy；
- frame-ancestors；
- Permissions-Policy；
- no-store 用于二维码、设置和操作响应；
- 静态指纹资源长期缓存。

## 11. 验收

- 未认证访问管理 API 被拒绝，或端口只能由受保护反代访问；
- 公网扫描不到 8632；
- 二维码响应不可缓存；
- Cookie/secret 不进入日志；
- proxy 凭据不进入镜像；
- backup/restore 有审计；
- deep readiness 的失败不泄露本地路径；
- Emby API key 仅使用 secret ref；
- 安全模式在总览页可见。
