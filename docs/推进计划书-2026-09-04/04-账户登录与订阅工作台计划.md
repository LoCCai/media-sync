# 账户登录与订阅工作台计划

> 执行切片校准（2026-09-05）：Execution 0051 已实现七平台能力契约、共享草稿校验、登录专用预检、精确 LoginSession QR、三步订阅向导与安全 policy/checkpoint 摘要。Execution 0052 已交付持久登录 Operation 历史、统一 Operation SSE、跨 coordinator 两阶段取消与登录 subject/event 关联；冻结完整套件 2315 passed、3 skipped，全部仓库门通过。订阅 pause/resume/delete 审计没有随 0052 交付，继续后移到 0055；真人登录仍由 Execution 0047 保持 `NOT_RUN`。

## 1. 目标

把当前“添加账户—点击扫码—等待二维码”的简单流程升级为可解释、可恢复的七平台工作台。

## 2. 账户状态模型

页面不只展示 `auth_status`，应组合：

- Account 状态；
- 最新 LoginSession；
- 浏览器 profile 资格；
- checkout/runtime 深度预检；
- 最近登录 Operation；
- 最近平台错误；
- 是否需要重新认证。

建议 UI 状态：

| UI 状态 | 含义 |
|---|---|
| Ready | 运行时通过，尚未登录 |
| Authenticating | 登录子进程运行中 |
| QR available | 二维码可扫描 |
| Authenticated | 保存会话有效 |
| Expired | 会话已过期 |
| Blocked | checkout、浏览器、许可证或路径预检失败 |
| Account busy | 同账户已有 child 持有锁 |
| External challenge | 平台风控、验证码或地区挑战 |

## 3. 登录前预检面板

每次启动登录前显示：

```text
✓ 数据库
✓ 上游锁文件
✗ Checkout tracked blob
— 浏览器运行时
— Profile 写权限
✓ Xvfb
✓ 许可证确认
```

任一 P0 项失败时禁用“启动登录”，直接显示固定错误码和修复链接。

## 4. 二维码生命周期

现状中二维码尚未生成时和登录已经失败时都可能返回 404。应改为：

- `202`: 登录正在启动，二维码尚未生成；
- `200`: 返回二维码；
- `410`: 登录尝试已结束，二维码不再可用；
- `404`: 账户或尝试不存在。

最好把二维码绑定到 `login_session_id` 或 `operation_id`：

```text
GET /api/v1/login-sessions/{id}/qr.png
```

避免同一账户多次尝试时取错文件。

二维码继续使用精确 LoginSession 端点有界轮询。0052 不另造登录专用 SSE；它在统一 Operation stream 中只发布封闭生命周期事件，例如：

```json
{"type":"operation","event":{"event_code":"operation_started"}}
{"type":"operation","event":{"event_code":"operation_entity_linked","subject":{"type":"login_session","id":"<uuid>"}}}
{"type":"operation","event":{"event_code":"operation_succeeded"}}
```

公开事件不包含二维码字节、profile 路径、原始异常、requester、lease、revision、幂等键或请求指纹。

## 5. 平台差异表单

每个平台应由后端暴露能力描述：

```json
{
  "platform": "bili",
  "login_methods": ["qr", "cookie_ref", "saved_session"],
  "creator_input": {
    "type": "numeric_id",
    "examples": ["2"]
  },
  "supported_shapes": ["video", "multipart", "dash", "flv"],
  "warnings": []
}
```

前端根据能力渲染输入，而不是硬编码七套猜测。

### Bilibili

- UID 数字；
- 多分 P、DASH、FLV 资格提示；
- 可选择较小 max_items；
- 不宣称番剧/直播。

### 小红书

- 作者 ID 或规范主页；
- 某些 detail 可能需要 secret ref；
- 多视频和实况形状资格提示；
- 过期权限应引导重新登录或更新 secret ref。

### 其他平台

根据真实能力矩阵显示：

- 输入格式；
- 已真人验证等级；
- 已知限制；
- 是否只支持元数据。

## 6. 订阅向导

分三步：

1. 选择账户和平台；
2. 验证作者标识并显示规范化预览；
3. 设置采集策略并确认。

策略字段：

- interval；
- max_items；
- request delay；
- headless；
- allow_full_history；
- optional cutoff；
- 当前 enabled 状态摘要；pause/resume 变更与审计后移到 0055。

对全历史路径必须醒目二次确认。

## 7. 订阅详情页

显示：

- 作者；
- 账户；
- 平台；
- 策略；
- schedule；
- cursor/水位摘要；
- 最近 SyncRun；
- 最近 Scheduler Job；
- 最近新增内容；
- 最近失败；
- 当前媒体资格；
- 手动 run-now；
- pause/resume（计划项，需 0055 鉴权与审计）；
- 安全删除订阅（计划项，默认不删归档内容，需 0055 保留/cascade 策略）。

0051/0052 尚未提供上述 pause/resume/delete 变更端点。后续实现删除时默认不得删除已归档内容，页面必须明确说明并记录经授权审计事实。

## 8. 会话恢复

支持：

- 重新认证；
- saved-session probe；
- profile 缺失诊断；
- profile 被占用；
- 上次登录异常清理；
- 取消正在运行的登录；
- 超时后自动收敛。

## 9. 安全要求

- 页面永不接收原始 Cookie；
- Cookie 只能以 `env:`、`file:`、`keyring:` 等不透明引用配置；
- 二维码不进入持久日志；
- 签名 creator URL 不持久化到普通 API；
- 登录错误只返回固定 code；
- 浏览器 profile 不提供下载；
- 登录 Operation 的启动、关联、取消与终态必须写入封闭事件；其他账户/订阅变更的完整审计后移到 0055。

## 10. 验收

- checkout 失败能在页面定位到具体 check；
- Bilibili 和小红书二维码协议与离线生命周期通过；真人二维码仍为 Execution 0047 的 `NOT_RUN`；
- 登录取消和超时后没有孤儿 Chromium；
- 重启后登录 Operation 历史可追溯；中断 callable 只保守协调，不自动恢复；
- 会话过期能进入明确状态；
- 同一账户并发登录被 409 阻止；
- 订阅向导生成的策略与 CLI 完全等价；
- 所有平台输入校验由后端能力契约支撑。

当前已交付任务中心能查看登录 Operation、固定错误码、安全结果、LoginSession subject 和事件时间线，并按后端 `allowed_actions` 请求取消。它不展示内部 requester/lease/revision/idempotency 状态，也不把订阅 pause/resume 审计伪装成已完成。
