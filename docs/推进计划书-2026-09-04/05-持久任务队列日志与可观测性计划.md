## 1. 交付问题与边界

0052 解决的是旧 `_OperationRegistry` 的以下问题：

- API 重启后操作历史消失；
- 多个 API 进程无法共享活动范围互斥和请求幂等；
- 取消只有进程内意图，缺少持久审计与 fenced owner 观察；
- Web 无法通过稳定 cursor 恢复事件；
- 五类 API 后台工作缺少统一、安全且有界的控制面投影。

它没有把所有后台执行统一为一种实体。`Operation` 表示一次 API 操作者请求，`Job`、`SyncRun`、`LoginSession`、`Asset` 与 `ExportRecord` 继续保有各自领域权威。既有 scheduler/supervisor Job 不会因 0052 自动变成 Operation；本轮不声明通用 broker、统一 supervisor 或进程死亡后恢复任意 Python callable。

## 3. Migration 0006 与持久不变量

`0006_operations_observability` 新增四张表：

### 3.1 operations

持久业务字段包括 kind、state、phase、进度、时间戳、target、correlation、取消时间、固定错误码、安全结果摘要与 operation 内事件水位。私有协调字段包括：

- 固定内部 `requested_by` 来源标签；
- `idempotency_key_hash`，仅为已校验原始 key 的 SHA-256 摘要；
- 不含请求正文的 canonical `request_fingerprint`；
- 服务端生成的 `exclusive_key`；
- repository revision；
- lease owner/token/expiry。

原始 `Idempotency-Key` 从不持久化。`requested_by` 不是调用方可写字段。上述 requester、digest、fingerprint、exclusive key、revision 与 lease 状态均不进入公开 API、SSE 或 Web。

数据库约束保证：

- kind、state、target、进度、时间戳、错误与 lease 形状合法；
- 每个活动 `exclusive_key` 至多一行；
- 适用的 `(kind, idempotency_key_hash)` 唯一；
- 终态释放 lease 且不可逆。

### 3.2 operation_events

事件只追加，具有 operation 内 `operation_sequence` 与全局 `stream_sequence`。事件事务会锁定并更新单例 counter 行后分配全局 cursor，避免数据库 sequence 分配顺序与提交顺序不一致导致 SSE 永久漏事件。

只允许十二个生命周期事件码、三个 level、封闭 from/to state、可选 subject 及白名单 `safe_context`。不接收原始异常、请求正文、URL、query、QR、路径、凭据、lease 或 worker 身份。

### 3.3 operation_subjects

该表保存有界多态关联，使一次 scheduler/pipeline Operation 可以关联多个 Job/Subscription/SyncRun，使下载与导出能关联实际 Asset/Author/ExportRecord，同时不假装一个 Job 代表整个 worker 调用。

### 3.4 operation_event_stream_state

单例行保存 `last_sequence` 与 `pruned_through_sequence`。它既提供首次连接 high-water，也让重连明确区分合法 replay、未来 cursor 与已裁剪 cursor。

## 4. 状态机、幂等与协调

封闭状态：

```text
queued → running → succeeded
                 → failed_retryable
                 → failed_terminal
                 → cancelled
                 → interrupted
```

create/replay 与 claim 在一个事务中完成，事务提交后才允许启动 callable。相同 kind、幂等摘要与请求指纹 replay 同一 Operation；相同 key 复用于不同 method/route/target/规范参数时返回固定冲突，且不回显 key 或请求值。

`OperationCoordinator` 服务端派生 worker owner，使用不可猜 lease token fencing，运行一个有界 heartbeat/cancel monitor，并通过事务内 subject hook 记录领域实体。SQLite 权威读取先取得 `BEGIN IMMEDIATE` writer reservation；`BUSY_SNAPSHOT` 等瞬时竞争最多以四个全新事务重试。终态写瞬时失败时保留 pending intent 交由 monitor 重试；并发 observer 会等待首个 `operation_cancel_observed` 提交，shutdown 则以统一 deadline 限制该等待并按时停止 monitor。

启动和列表/详情读取会有界协调过期 Operation：

- 有效其他实例 lease 保持不变；
- LoginSession/Job 存在无歧义终态时，以其持久事实收敛；
- 证据不足时收敛到 `interrupted`；
- 不自动重新执行丢失的内存 callable。

## 5. 两阶段协作取消

`POST /api/v1/operations/{id}/cancel` 只先设置 `cancel_requested_at` 并追加 `operation_cancel_requested`。取消请求不是终态；当前 fenced owner 观察后追加相应事件并在安全边界结束。

- 登录复用既有 cancellation signal；
- scheduler/pipeline worker 在下一 Job 前停止；
- 下载/归档/Emby 临界段不能被虚假强停；若工作已经安全完成，可以如实报告 `succeeded`；
- finish-versus-cancel 竞态由 lease 与持久领域事实决定，不按 HTTP 到达顺序猜测。

公开 `retryable` 由状态派生。当前 `allowed_actions` 只为尚未请求取消的 `queued|running` Operation 提供 `cancel`；后端 retry 端点尚未实现，前端不得自行制造状态转换。

## 6. 已实现 API 与 SSE

```text
GET  /api/v1/operations
GET  /api/v1/operations/{id}
GET  /api/v1/operations/{id}/events
POST /api/v1/operations/{id}/cancel
GET  /api/v1/operations/events
GET  /api/v1/support-bundle
```

五类既有 POST 接受严格、有长度/字符边界的 `Idempotency-Key`。私密 reference 只以领域隔离摘要进入 request fingerprint；调用方提供的 `worker_id` 仅作为弃用兼容输入解析，不参与持久所有权、事件或响应。

列表、详情与事件读取全部有界并使用 keyset/cursor。公开序列化只包含稳定业务投影与派生动作，绝不包含 requester、lease、revision、fingerprint 或幂等摘要。

SSE 行为：

- 新连接发送 `ready` 与当前 high-water，由客户端读取 200 项有界快照；
- 携带 `Last-Event-ID` 的重连严格补发该全局 cursor 之后的已提交事件；
- 畸形或未来 cursor 返回固定 400；已裁剪 cursor 返回固定 `410 operation_event_cursor_expired`；
- batch、数据库轮询、keepalive 与连接存活时间均有界；
- 同一浏览器只需一个 Operation stream，不为每个任务新建连接。

API lifespan 在 Operation 数据库暂不可用时仍允许 health 启动；Operation 端点以固定 `operation_store_unavailable` 失败，而不是返回假成功。

## 8. 窄化支持响应

`GET /api/v1/support-bundle` 返回 `application/json` 与 `Cache-Control: no-store`。名称保留“support bundle”，但实现有意是最大 16 KiB 的 canonical JSON，而不是 ZIP。

固定内容仅包括：

- project name/version；
- expected/current schema revision 与 readiness；
- Account、Subscription、Author、Content、Asset、Job、Operation 聚合计数；
- 全部封闭 Operation state/kind 计数；
- 最近最多 200 个失败 Operation 聚合成最多 32 个固定错误码计数。

它不读取或返回 Operation ID、时间线、事件正文、请求、异常、路径、URL、QR、配置键/值、系统/Docker/进程摘要、profile、测试资格明细或原始 error payload。编码后对完整输出字节执行第二次 URL/query/path/QR/secret/exception/sentinel 扫描；数据库失败只返回 `support_bundle_database_failed`。
