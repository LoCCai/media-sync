## 1. 当前问题

当前 REST API 的 `_OperationRegistry` 位于进程内：

- 服务重启后历史消失；
- 无法跨 API 容器和 supervisor 统一查看；
- 无法恢复长任务的前端状态；
- 无法把登录、同步、下载和导出放到一个稳定时间线；
- 页面轮询只能看到结果摘要。

media-sync 已经拥有持久 Job、SyncRun 和 Asset 状态，下一步应让 Web 操作也成为持久一等对象。

## 2. 统一关系模型

```text
Operation
  ├─ LoginSession
  ├─ Scheduler Job
  │    └─ SyncRun
  │         └─ Content
  │              └─ Asset
  │                   └─ Asset download Job
  └─ Emby export Job
```

Operation 表示操作者请求；Job 表示持久执行单元；Event 表示状态变化。

## 4. 状态机

```text
queued
  → running
  → succeeded
  → failed_retryable
  → failed_terminal
  → cancelled
  → interrupted
```

API 进程退出时仍为 running 的 Operation，在启动恢复时根据关联 Job 判定：

- Job succeeded → Operation succeeded；
- Job retryable → Operation failed_retryable；
- 没有持久执行实体 → interrupted；
- 不允许永久 running。

## 6. 实时更新

使用 SSE：

```text
GET /api/v1/operations/events
```

事件带单调 sequence。浏览器重连时发送 `Last-Event-ID`，后端从数据库补发。

避免：

- 每三秒全量轮询；
- 每个任务一个连接；
- 把完整日志塞进 Operation result。

### 7.2 脱敏

统一 sink：

- 常见 token/cookie 名称；
- SecretValue；
- Authorization；
- URL query；
- 二维码；
- profile 路径；

固定错误码可以展示，原始异常只允许在开发模式和二次脱敏后进入本地文件。

- 实时追加；
- 自动滚动；
- 下载支持包；
- 错误数量；
- 模块和任务筛选。

## 8. 支持包

一键生成压缩包，只包含：

- Docker/系统摘要；
- deep readiness；
- schema revision；

## 9. 指标

最低指标：

- sync 成功/失败；
- 新内容数量；
- 下载成功/失败；
- 下载字节；
- 归档容量；
- queue depth；
- 最老等待任务；
- 登录过期账户；
- Emby 待发布作者；
- 连续失败订阅。

第一版可以由聚合 API实时计算；规模增大后再做日汇总表。

## 10. 操作权限

动作根据领域状态动态开放：

- running：可取消；
- failed_retryable：可重试；
- failed_terminal：只允许查看，需专门恢复动作；
- verified：只允许校验；强制重下载暂不开放；
- subscription enabled：可暂停；
- paused：可恢复。

前端不能自己推断状态转换，后端返回 `allowed_actions`。

## 11. 验收

- 服务重启后操作历史存在；
- API 和 supervisor 产生的任务统一可见；
- SSE 断线重连不丢事件；
- 任一 Operation 可追到 Job/SyncRun/Asset；
- 不存在永久 running；
- 失败状态、error code 和 retryable 一致；
- 支持包经过秘密扫描；
- 一万条事件下页面仍可分页和筛选。
