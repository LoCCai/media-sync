# 产品需求

- 状态：架构基线
- 适用版本：`media-sync` 0.x
- 上游范围：[`upstreams.lock.json`](../upstreams.lock.json)

## 产品说明

`media-sync` 是一个可自托管、本地优先的创作者内容归档服务。它协调用户授权的平台登录会话，以克制的频率进行增量采集，保存原始内容及归一化元数据，并生成确定性的 Emby/Jellyfin 媒体库。

## 功能需求

### 账户与登录

- **AUTH-001** — 为七个平台分别建模账户。
- **AUTH-002** — 只展示当前适配器和平台真正实现的登录方式。
- **AUTH-003** — 在上游能力允许时支持交互式二维码、Cookie 和已保存浏览器会话；手机号登录只对验收过的平台开放。
- **AUTH-004** — 原始 Cookie 不得进入 SQLite、配置文件、日志、命令行参数或 Git，只保存凭据引用并在进程启动时解析。
- **AUTH-005** — 浏览器配置按“平台 + 账户”隔离，登录过期状态可观察。

### 创作者订阅

- **SUB-001** — 通过平台创作者 ID 或规范主页 URL 添加订阅。
- **SUB-002** — 以“平台 + 稳定远端创作者 ID”强制唯一，同时允许多个账户访问同一位作者。
- **SUB-003** — 支持启用、暂停、立即运行和删除订阅，默认不删除已归档内容。
- **SUB-004** — 为每个订阅配置采集间隔、单次扫描数量上限和可选的发布时间截断。
- **SUB-005** — 持久化 cursor/水位与下次运行状态，保证重启后仍幂等。

### 采集与归一化

- **SYNC-001** — 每次同步运行使用独立的任务目录，并保留脱敏 manifest 与有界日志。
- **SYNC-002** — 增量导入 JSON 与 JSONL，容忍最后一行 JSONL 被截断，隔离畸形记录。
- **SYNC-003** — 按稳定平台键 upsert 创作者与内容记录；重试运行不得产生重复内容。
- **SYNC-004** — 归一化视频、图片/图集、文本/文章与混合帖子，同时保留完整原始记录以便向前兼容地重新处理。
- **SYNC-005** — 发现有序媒体 Asset、规范源 URL、发布时间、标题/正文、创作者身份与可用的互动字段。
- **SYNC-006** — 应用有界并发、可配置的请求间隔、带抖动的指数重试，以及针对重复风控/登录失败的熔断器。

### 媒体与 Emby/Jellyfin

- **MEDIA-001** — 通过临时文件原子化下载 Asset，并在 HTTP 允许时支持续传。
- **MEDIA-002** — 校验协议、重定向目标、内容类型与配置的大小上限；对音频/视频做结构化探测，组件需要合并时使用有界 FFmpeg stream-copy，仅在最终校验后计算 SHA-256。
- **MEDIA-003** — 保留原始 Asset，并记录来源、下载状态与失败原因。
- **EMBY-001** — 把每位创作者导出为带 `tvshow.nfo`、创作者海报与按年分季的 Emby/Jellyfin 剧集。
- **EMBY-002** — 把可播放视频帖子导出为剧集，使用稳定的 `SyyyyE...` 命名并配套剧集 NFO。
- **EMBY-003** — 图集/文本与其 NFO 并列保留，并可选渲染 FFmpeg 幻灯片 MP4，使图片/文本帖子可在 Emby 视频库中播放。
- **EMBY-004** — 使用 XML 安全取值、平台作用域唯一 ID、来源链接、发布日期、剧情文本、标签、工作室/平台与创作者演员元数据。
- **EMBY-005** — 渲染到暂存路径并原子替换变更的 sidecar；重复导出必须确定性。

### 接口与运维

- **OPS-001** — 提供一个覆盖数据库初始化、账户/订阅管理、同步、导入、导出、体检与服务器启动的 CLI。
- **OPS-002** — 提供带版本号的本地 REST API，覆盖等价核心操作与健康/就绪端点。
- **OPS-003** — 输出结构化、脱敏的日志，暴露运行/条目失败状态而不暴露凭据。
- **OPS-004** — 支持 SQLite 备份/恢复与 schema 迁移；使用 WAL 模式与单写者事务策略。
- **OPS-005** — 提供 Docker 与原生安装说明；交互式浏览器登录仍由宿主机协助完成。

## 安全与合规需求

- **SAFE-001** — 首次现网运行前，用户必须显式确认所选爬虫适配器的许可证与平台条款。
- **SAFE-002** — 默认每账户一个并发爬虫、关闭评论、小数量上限与非零延迟。
- **SAFE-003** — 不绕过验证码、付费墙、私享账户控制或平台访问限制。
- **SAFE-004** — 拒绝非 HTTP(S) 的远端 Asset URL，并阻止下载路径逃逸出配置根目录。
- **SAFE-005** — 对常见 Cookie/token 名称与用户提供的机密值在错误和子进程输出中脱敏。

## 质量需求

- Windows、Linux 与 macOS 上的 Python 3.11+；UTF-8 路径与非 ASCII 创作者标题为一等公民。
- 核心操作有类型检查、lint 与单元测试；数据库、桥接导入与 Emby 输出有集成测试。
- 干净 checkout 无需网络、账户、浏览器或 MediaCrawler 即可运行确定性测试。
- 现网测试显式选择加入，绝不在 CI 中运行，且只记录脱敏证据。
- 数据库与输出 schema 均有版本；上游特定的原始 payload 未经版本化封装绝不泄漏到公开领域接口。

## 0.x 明确不做

- 不做大规模关键词抓取、评论仓库或无限制站点爬取。
- 不绕过平台保护或自动破解验证码。
- 不宣称拥有 MediaCrawler 商业使用权，也不再分发其源码。
- 不做云端多租户、直接暴露公网或共享密钥存储。
- 不追求与 bili-sync-up 全部高级 B 站功能逐字节一致。

## 发布验收

自动化验收是必要条件但不是充分条件。每个平台还必须在用户授权账户下记录登录、一次作者扫描、增量重跑、媒体获取和 Emby 重扫结果。缺少账户或遇到真人交互挑战时必须标为 `NOT_RUN` 或 `BLOCKED_EXTERNAL`，不得记为 `PASS`。
